# 鱼岛 Next 系统架构基线

状态：已采用。版本：1.0。日期：2026-11-11。

本文件是后续实现、代码评审和架构调整的依据。新增功能必须先确定所属模块和依赖方向，再编写代码。变更基线需同步 ADR、实现与验证，禁止用“临时实现”长期绕过边界。

## 1. 目标与当前范围

目标：在保留既有后端兼容能力的前提下，建设可维护、交互流畅的 React 聊天客户端；支持微信、飞书、钉钉等外壳与第三方声明式皮肤包。

本轮已完成：独立 Vite 工程、严格 TypeScript、路由入口、Zustand 外观状态、CSS 变量、Radix 弹窗、四种内置主题、模块规范、检查脚本与基础测试配置。

当前新增：微信风格工作台外壳、公开热榜接口与来源/分类/搜索/刷新交互。首页进入热榜，初始化页面迁至 /foundation。详见 ADR-002。

单个来源详情采用只读消息气泡，总览保留卡片；主内容与来源区通过 shared/ui/ScrollArea 统一原生滚动体验。详见 ADR-003。该消息样式不代表已连接真实聊天。

ADR-004 更新呈现：总览卡片固定高度、内部完整榜单滚动；主内容页头移除搜索和刷新，保留错误重试。WorkspaceShellSlots 新增可选 footer，承载固定在消息区下方的演示输入框与工具栏。输入框允许编辑但不会发送，已按用户要求标为演示。

ADR-005 进一步按旧摸鱼岛源码还原总览视觉：蓝色缎带、同行更新时间、400px 榜单区、彩色排名块与火焰热度，移除卡片底栏；标题进入消息详情。设置可选择总览来源（当前会话内存状态），全局外壳和演示输入区不受影响。

ADR-006 接入旧摸鱼岛账号/邮箱密码登录、Sa-Token 会话恢复、按后端隔离的凭证存储、跨标签页同步、退出和 /chat 路由鉴权。domain/auth 定义端口；infrastructure/auth 适配 HTTP/存储；features/auth 独立管理会话，app 组装 Provider、登录页与守卫。公开热榜不受登录限制。恢复网络错误保留凭证，认证过期才清理，退出警告由全局 AuthNotice 跨路由呈现。

ADR-007 将登录入口更新为当前页面上的路由弹窗，使用 backgroundLocation 保留热榜状态；直接进入 /user/login 则以热榜为背景，关闭可返回。消息气泡移除可见排名，分类与平台缎带统一使用微信主题强调色，总览排名保留。

账号入口固定为导航栏首项：游客显示“鱼”占位并打开登录弹窗，已登录显示当前用户头像并打开用户菜单；底部不再重复显示账号入口。手机横向导航同样将账号入口放在最左侧。

ADR-009 迁移 `/oauth2/authorize` 摸鱼岛 SSO 授权页；domain/sso 定义端口，infrastructure/sso 适配公开应用信息与授权接口，features/sso 管理授权交互，app 组合鉴权与回调导航。保留旧版样式和参数协议。

尚未完成：注册、找回密码、第三方登录回调、完整消息类型、断线补拉与历史缓存、完整平台聊天外壳、皮肤导入、性能基线采样。已安装依赖不等于功能已实现。禁止从旧项目复制整个聊天页面。

ADR-008 新增企业微信内置主题、工作台导航主题弹窗与皮肤 ID 本地持久化。复用当前工作台布局，不重挂载热榜或输入区；内置 token 扩展不改变第三方导入白名单。

ADR-010 新增鱼小圈分层模块与鉴权懒加载路由 `/moments/fish-circle`，复用旧动态、评论和上传协议；app 注入凭证与账号生命周期。工作台支持业务侧栏名称。详见 ADR-010。

ADR-011 补齐内置主题的双向气泡、导航交互和内容背景变量，主题预览与实际工作台共用配色；第三方导入白名单保持不变。

ADR-012 按旧版截图重做鱼小圈右侧封面、动态双栏与窄屏单栏；profile 端口读取账号封面，评论预览与更多操作保持组件内状态。详见 ADR-012。

ADR-013 新增 WPS 表格内置配色，复用现有主题注册表、预览与持久化；不改变工作台布局、业务状态或第三方皮肤白名单。

ADR-016 扩展 WPS 模式为顶部功能区。app 显式将 wps 皮肤映射到 wps 外壳标识，复用稳定的工作台布局组件，通过 navigationLayout 调整网格而不重挂载内容；聊天、热榜和鱼小圈成为顶部独立路由标签，账号和主题入口保留在办公工具区。详见 ADR-016。

ADR-017 新增 WPS 热榜多维表格呈现，由 app 注入 table 展示变体，复用同一请求与来源选择状态。表格提供查找、来源/分类筛选、排名/热度排序和刷新；WPS 热榜隐藏侧栏，手机优先展示标题与来源。主题按钮使用包含内边距的固定列宽，避免控件越界。

ADR-015 仅将鱼小圈左侧发现栏更新为微信样式并交换热榜/鱼小圈图标；右侧保留 ADR-012 的封面、卡片和双栏。修复评论满页解码把数组序号误当嵌套深度的问题。

## 3. 目录与职责

```text
src/
  app/                     启动、路由、Provider、依赖组装、页面级组合
    pages/                 薄页面，只组合功能、外壳和路由参数
    providers/             应用生命周期与上下文
    styles/                全局 reset、默认 token、可访问性规则
  domain/
    auth/                  用户、凭证和认证/存储端口
    chat/                  消息/会话模型、纯规则、服务端访问端口
    hot-board/             热榜来源、条目、读取端口
  features/
    auth/                  会话控制器、表单、头像入口及全局提示
    appearance/            内置外观选择状态与皮肤 ID 本地持久化
    hot-board/             热榜请求生命周期、筛选与业务展示
    chat/                  群聊界面、在线成员、独立草稿、消息 store 与实时用例
    conversations/         后续：会话列表、选中态、分页
    skin-import/           后续：校验、预览、应用、回滚流程
  infrastructure/          HTTP 与 WebSocket 协议适配；后续缓存
  shells/                  微信/飞书/钉钉布局与只读外壳契约
  skins/
    builtin/               内置皮肤配置、类型与注册表
  shared/
    ui/                    无业务含义的 Button、Dialog 等基础组件
    lib/                   后续：真正跨业务的纯工具，禁止杂物 utils
tests/e2e/                 浏览器流程验证
docs/                      架构、组件、皮肤、性能与决策记录
```

仅在首个实现进入时建立 feature 子模块；禁止为未来能力制造大量空类、空 Hook 或占位服务。当前 domain 与 shells 的接口是边界种子，需在接入真实 API 时细化。

## 4. 依赖方向（必须）

- app 可以组合所有层，是依赖注入与跨功能流程的入口。
- domain 只包含 TypeScript 模型、纯规则、端口；不能依赖 React、store、DOM、网络客户端、样式或 infrastructure。
- infrastructure 只依赖 domain 与 shared/lib；实现端口，不能导入业务组件、store、外壳，不得弹 toast 或操作 DOM。
- features 可依赖自身内部文件、domain、shared，以及纯 skins 配置；不能直接依赖 infrastructure、app、shells 或其他 feature。
- shells 可依赖 React、domain 类型、shared 和 skins 配置；通过 props/slots 接收内容与回调，不直接订阅业务 store、发请求或持有连接。
- skins 是纯配置与校验逻辑，不持有 React 状态，不访问网络、业务或 DOM。应用 token 的 DOM 副作用由 app Provider 承担。
- shared 不能反向导入业务层；组件通过 props 获得数据。

跨功能协作由 app 的控制器/组合组件协调，或通过 domain 定义的端口注入；禁止以全局 event bus 替代清晰依赖。不为简单函数引入 DI 容器。

跨目录统一使用 `@/`，跨模块仅导入 `index.ts`。模块内部使用 `./` 相对导入；禁止 `../` 导入。ESLint 对静态 import 提供基础门禁，动态 import、export from 和新路径的边界仍须评审，不能把 lint 当成完整架构证明。

## 5. 聊天数据流与状态所有权

```text
后端 DTO → infrastructure 解码与映射 → domain 消息/事件
   → feature 用例 → 消息 store → 精确订阅的消息行
用户输入 → 输入框本地草稿 → 发送用例 → domain 端口 → infrastructure
app 负责注入端口与组装外壳；外壳不感知后端协议。
```

| 状态                   | 所有者                  | 更新范围                  |
| ---------------------- | ----------------------- | ------------------------- |
| 消息实体与会话消息 ID  | chat feature            | 对应会话、对应消息行      |
| 会话摘要与未读         | conversations feature   | 对应摘要行                |
| 输入草稿、输入法组合态 | Composer 或独立草稿模块 | 输入区域                  |
| 当前会话与跨功能导航   | app 组合层              | 页面组合                  |
| 打开菜单、悬停、展开   | 最靠近使用位置的组件    | 组件局部                  |
| 外壳 ID 与皮肤 ID      | appearance feature      | 外壳装配和 token Provider |
| HTTP 请求生命周期      | 所属 feature 用例       | 对应功能状态              |

消息按 `messagesById` 与 `messageIdsByConversation` 归一化，不按数组下标识别消息。每行订阅自己的实体；列表订阅 ID 序列。稳定排序需要服务端序列号，无法取得时采用明确的时间与 ID 次级排序，并记录兼容限制。

入站消息幂等；历史与实时合并去重；服务端确认合并临时消息时维护 clientMessageId 映射和稳定渲染标识。撤回、编辑、重试、发送中、失败、已确认均显式建模。不能因皮肤切换重连或丢弃草稿。

## 6. 通信与缓存约束

聊天消息区每次从其他菜单返回时重新请求最新历史页，保留账号草稿与已有消息，并对断开的账号连接立即重试；已连接或握手中的连接复用。主题/模式切换不触发该流程。详见 ADR-036 的返回刷新补充。

- 连接由 app 生命周期统一拥有，功能使用可释放订阅。StrictMode 重挂载不能产生重复连接/订阅。
- 重连采用指数退避、抖动和上限，区分离线、认证失效、主动关闭与可恢复错误。
- 重连恢复依赖后端 cursor/seq 补拉；没有协议支持前不得宣称无丢失或 exactly-once。
- HTTP 支持 AbortSignal；切换会话后丢弃旧响应，取消请求不得误报业务失败。
- 外部输入先当作 unknown，再校验、映射。网络失败是可识别结果，不吞错，不把错误字符串当成功数据。
- 缓存按账号命名空间隔离；登出清理内存、连接、订阅和敏感持久数据。不能将服务端分页历史无限累积到内存。
- 认证方案沿用后端实际协议；确认前不自动把令牌写入 localStorage 或 URL。日志脱敏。

## 7. 外壳、组件与皮肤

ADR-026 统一 shared/ui/Button 的桌面紧凑尺寸及主题动作色；手机保持 44px 触控高度，资料弹窗移除固定宽度和橙色按钮覆盖。详见 ADR-026。

ADR-025 为 ScrollArea 增加预留滑轨空白的 gutter 呈现变体，个人资料编辑区采用该变体，避免滑轨与表单及焦点环重叠。详见 ADR-025。

ADR-024 明确统一控件外观标准，禁止原生 select 系统展开列表和浏览器业务确认框；shared/ui/Select 封装 Radix Select，统一称号、WPS 来源及分类的选值交互，评论上传使用统一按钮入口，ESLint 阻止再次引入原生 select/datalist。整改与验证记录在 docs/audits/native-control-style.md，详见 ADR-024。

ADR-021 在 auth 模块迁移完整旧版个人信息弹窗，包括用户名/头像/默认头像/朋友圈背景/简介、邮箱绑定、称号、会员信息与破蛋日。修改确认后原位更新会话并回读，不重挂载业务内容。邮箱绑定、称号选择即时独立生效，基础资料在保存时提交。详见 ADR-021。

ADR-020 将鱼小圈更多操作改为非模态锚定菜单，shared/ui/DropdownMenu 按需包装 Radix Dropdown Menu，业务权限与后续确认流程保持在 feature。详见 ADR-020。

ADR-019 增加与 skinId 独立的明亮/暗夜模式。appearance 持有并分别保存两种选择，skins 纯函数组合主题 token，app Provider 应用 token 和根节点模式属性；全局模式变量覆盖业务局部色。两种切换均不得重挂载业务或重取数据。暗夜基础背景为 `#191A1C`，详见 ADR-019。

一个聊天内核，多套外壳。外壳只摆放导航、会话区、标题区、消息区、输入区和辅助区。消息行为只实现一次。平台特有外观通过样式/受限呈现变体实现，不能重写发送、历史、未读和滚动逻辑。

详见 [组件规范](./component-standards.md) 和 [皮肤协议](./skin-spec.md)。组件规范与本文件具有同等约束力。

## 8. 质量门禁

- `npm run check`：格式、lint（零警告）、严格类型、单元测试、生产构建。
- `npm run test:e2e`：真实浏览器功能流程；当前提供初始化页换肤和弹窗验证。
- 业务纯规则优先单元测试；连接、去重、历史锚定、草稿、失败重试做集成/浏览器验证。禁止为每个低风险包装组件写镜像测试。
- 组件视觉变更验证桌面与窄屏、键盘操作、焦点、空状态与错误状态。
- 性能目标与场景见 [性能规范](./performance.md)。初始化页面的体积或测试结果不能代替完整聊天场景测量。
- 引入依赖说明用途、替代方案、许可证及首屏影响；没有需求不引入微前端、DI 容器或第二套 UI 框架。

## 9. 实施顺序

1. 明确旧后端协议、鉴权、消息类型、排序和补拉能力；形成 DTO 映射与兼容说明。
2. 实现单一外壳下的登录、会话、纯文本消息、历史、断线恢复；先验证正确性和性能。
3. 加入图片、引用、撤回等消息能力，再接入第二外壳验证内核复用。
4. 实现完整 token 协议与皮肤校验器，再开放第三方皮肤导入。
5. 红包、投票、游戏、阅读等作为独立可懒加载功能迁移。

每个阶段都应可独立运行和验收；不一次搬运旧系统全部逻辑。

用户已要求优先交付微信基础外壳和热榜，这一独立公开功能先于聊天实施，不改变后续聊天迁移顺序。工作台使用 WorkspaceShellSlots（navigation/sidebar/header/content）；聊天仍使用 ChatShellSlots。二者都是纯布局契约。

ADR-022 将鱼小圈筛选与操作收拢为封面右上角图标，复用鱼小圈领域端口接入旧版互动提醒分页、已读、删除及动态详情。通知状态由独立组件持有，不随外观切换重置。详见 ADR-022。

ADR-023 将通知优化为非模态紧凑浮层，发布弹窗参考旧版 PublishMomentModal 重建；共享 Dialog 默认行为保持不变，详见 ADR-023。

ADR-022 的关联动态详情改为工作台主内容区内切换，由 CircleFeed 持有选择，复用 contentScroll=false 与独立 ScrollArea；列表保持挂载并隐藏，返回恢复原滚动、草稿及数据。详情不使用弹窗，图片预览等独立任务沿用现有 Dialog。

ADR-022 补充评论通知定位：infrastructure 保留通知发送者编号，feature 按已有评论分页匹配通知内容、展开祖先回复并定位高亮；定位状态与分页由评论功能拥有，不进入页面或外壳。旧协议缺少评论编号时显式处理无法唯一匹配与找不到的情况，自动查找有界且可取消。

ADR-022 的详情按主内容区可用宽度采用左内容/右评论布局，窄屏上下排列；同一业务组件通过 CSS container query 呈现。评论列表独立限高滚动，标题、输入与反馈分区；通知定位只滚动评论内层视口，保持宽屏正文位置。该嵌套滚动为用户明确要求的阅读场景。

ADR-029 迁移公开关于页 /about，app 组合发现导航，features/about 管理复制与图片状态，保留旧版反馈及功能介绍并注明旧版能力范围；详见 ADR-029。

ADR-029 补齐关于五项菜单和旧 /rank/* 路由，domain/about 与 infrastructure/about 分离打赏分页及订单协议，app 注入会话；福利图片与其他产品仍由 about feature 展示。

ADR-032 手机工作台采用分层导航：外层热榜与发现使用底部 Tabbar，内层隐藏全局菜单并提供返回；朋友圈隐藏手机页头，返回入口位于封面左上角，发现根页隐藏手机菜单内的重复标题。外壳通过 hideMobileHeader 纯布局属性呈现，返回发现由 app 注入，桌面布局不变。见 ADR-032。

ADR-033 手机视口统一隐藏原生与 Radix 可视滑轨，保留滚动逻辑、焦点和 gutter；桌面保持原行为。见 ADR-033。

ADR-034 统一全系统滚动分页：shared/ui/InfiniteScroll 提供边界观察器和通用分页 Hook，feature 负责领域适配与请求生命周期；后端页码协议保留，界面移除页码及翻页/加载更多按钮。详见 ADR-034。

ADR-032 补充发现内层手机页头仅返回呈现：游戏、阅读、伙伴、关于及人生重开通过 app 组合 `mobileHeader="back-only"` 隐藏标题与菜单，关于分区导航移入正文；桌面与朋友圈封面返回保持原有布局。
