# ADR-069 聊天用户卡片

状态：已采用。日期：2026-11-15。

## 原因与决策

消息名称与在线成员名称统一打开按需读取的用户卡片，备注编辑保留为卡片内动作及原消息菜单动作。domain/account-tools 定义 UserCardPort，infrastructure/account-tools 适配现有资料、关注和禁言协议；features/chat 持有独立卡片宿主与请求状态，app 注入端口、账号与跨功能导航。不将弹窗状态放入页面、消息 store 或输入草稿，不增加连接。

桌面和手机共用层叠卡片布局以及 Dialog、reserved ScrollArea、Button、Select 和主题语义变量。带封面时原图铺在正文背景，资料使用半透明面板；没有封面时使用主题画布和实色面板。空资料、请求失败、图片失败及操作反馈明确呈现；关闭/切换账号取消请求。外观切换保留卡片状态且不参与请求依赖。

旧版封禁和修改积分只有模拟成功，不迁移；不伪造在线状态和“刚刚活跃”。禁言复用真实接口且仅管理员可见，提交前明确确认；黑名单沿用账号隔离的浏览器存储。其他功能通过 app 组合已有可用入口，不以本人页面冒充他人资料。

## 替代方案

### 查看用户的关注与粉丝

聊天卡片的关注、粉丝统计兼作名单入口。app 注入 account-tools 的同一名单组件和只读目标，使用专用的 `/follow/user/following` 与 `/follow/user/followers` 登录接口按用户 ID 查询，兼容原本的本人列表接口。后端复用分页及批量资料映射，互相关注指该卡片用户与名单中岛友之间的关系，他人视图仅展示公开资料与关系，不返回关注时间。专用接口避免前端连接旧后端时把本人名单误显示为他人名单。

卡片弹窗切换为固定标题及返回入口的单列名单，切回时归还焦点并保留卡片状态；离开时取消分页，主题、明暗与聊天连接保持独立。替代方案是另开一个聊天弹窗或实现第二套滚动分页，均会重复现有状态与焦点管理。验证覆盖目标 ID、鉴权、互关、空名单、失败重试、连续滚动和返回焦点，以及全部主题、明暗与 1280/375/390 布局。

不复制旧版聊天巨型弹窗；不让消息行各自持有资料请求，避免重复状态和对列表的额外订阅。继续直接打开备注无法满足用户查看资料的任务。

## 验证

资料区按有封面、无封面两张参考图调整：桌面宽度分别为 520px 和 420px，头像跨过资料面板上缘，昵称、称号和简介集中在身份区。关注和粉丝计数共享主题浅底，空间入口显示图标及文字，手机把统计和操作分行。使用合成数据验证背景覆盖、头像交叠、无封面与封面失败、命中尺寸及滑轨显隐，并沿用关注、备注、管理和导航回归。

修复紧凑卡片关闭入口：共享 Dialog 的关闭按钮建立正文之上的局部层级，防止后绘制的定位滚动视口拦截点击。保留 Radix Close、44px 命中区、Esc 与焦点返回，不改变 Portal 或业务状态。回归覆盖关闭按钮中心及内部多点命中、加载/空/错误/短资料/长内容/封面状态下的鼠标和触屏关闭，以及 Enter/Esc。

两种卡片高度随内容变化，资料视口按可用高度封顶并保留 reserved gutter，阅读长简介时正文滚动、页脚固定。管理员查看他人资料时，右上角关闭按钮左侧的齿轮打开独立管理弹窗，使用共享 Dialog、Select 和 reserved ScrollArea。齿轮固定在资料滚动区外，首次打开才读取禁言状态，关闭管理弹窗后焦点回到齿轮，并保留已加载状态、时长和操作进度，关闭资料卡片时取消请求。原内联展开方案会挤占资料正文并受滚动位置影响。回归验证有无封面、禁言加载与重试、选择器及弹窗分层关闭、焦点返回、触屏命中和外观切换。资料解析兼容后端 JsonConfig 将 Long 序列化为十进制字符串的协议；关注/粉丝数量保持安全非负整数校验，不将空值当作 0。

用户卡片隐藏积分。公开资料接口当前未返回地区，聊天历史与实时消息已携带发送者的国家和地区快照。由共用消息解码器保留有效地区，在消息名称打开卡片时作为资料地区的回退。没有快照的在线成员入口及没有有效地区的消息仍显示“未提供”。复用消息快照避免新增查询或为账号推断当前位置，外观切换不参与数据读取。

用户卡片恢复旧版的完整称号栏。现有 `user/get/vo` 详情响应通过专用视图附带佩戴称号和已获称号 ID。老服务缺少这些字段时，使用历史、实时消息和在线名单已经提供的称号快照。佩戴称号优先，其他有效 ID 去重后按原顺序展示，遇到可用宽度不足时换行。普通消息仍仅显示佩戴称号。沿用原请求及权限，避免为每张卡片额外发起称号查询或使用管理员端口。验证新旧响应、数字与字符串 ID、重复和无效数据，以及全部主题、明暗模式和三种视口的徽章换行与背景对比。

执行 npm run check；用合成协议数据验证全部注册主题 × 明暗 × 桌面/375px/390px 的打开、加载、失败重试、空资料、关注、备注、黑名单、关闭焦点、滚动留白及草稿/连接保持。覆盖资料地区优先、消息快照回退和地区缺失。真实账号与服务端权限需单独联调，不记录真实账号资料。

## 卡片收藏

用户卡片在宠物和农场旁提供「卡片收藏」入口。app 按需装配 pet 收藏面板，聊天弹窗提供收藏视图的宽度及返回焦点。桌面三列、手机双列，插画区统一高度，竖版插画等比缩放并居中显示全图。卡名可自然换行，同一行的卡框按最长卡名撑高，品质和星级栏贴底对齐。沿用共享滚动分页、加载反馈和语义颜色。

登录后通过 `GET /pet/cards/collection?userId=…&page=…` 读取目标用户在 ADR-104 中保存的正式收藏。Mapper 在分页前按闪耀、传说、史诗、精良、普通排序，同品质以卡牌编号稳定排序。每张卡片提供卡名、图片、品质和星级。分页和取消归 pet 面板管理，主题切换不重新查询。

首次读取收藏时，同一接口附带目标用户的抽卡等级、本级已拆和所需包数。服务端复用 ADR-104 的正式计数和等级阈值，最高 60 级。共享分页保留首批摘要，列表续载继续只读取收藏。单独请求摘要会增加打开收藏时的请求和状态，用累计包数在前端计算则会重复等级规则。旧接口未返回摘要时仍能正常查看收藏。

抽卡等级固定在列表上方，主题语义色进度条与包数文字共同表示进度，满级显示「已满级」。无收藏的用户也能看到真实等级与进度。

验证目标账号、首批等级与进度、满级、空收藏与旧接口兼容，以及跨页顺序、加载、失败重试、滚动续载和返回焦点。按全部注册主题、明暗模式及桌面、375px、390px 视口检查正方形与竖版插画混排、长卡名换行及同行对齐。
