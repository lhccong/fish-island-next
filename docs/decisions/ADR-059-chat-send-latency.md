# ADR-059 聊天发送延迟

日期：2026-11-14。采用。

## 原因

本地 HTTP 实测稳态 624～706ms，调用栈多次停在 Redisson 同步命令。发送前还同步调用最长 5 秒的外部 IP 定位；失败不缓存。前端收到已落库的服务端广播后仍等待 HTTP 结束，放大等待感。

## 决策与影响

- 后端保留账号/clientMessageId 分布式锁、七天预留及回执、落库先于广播；用单次 Lua 读取预留或原子生成递增毫秒 ID，再通过原 Redisson codec 写入预留，减少新消息的两次 Redis 往返。旧回执按原 codec 解码，避免将 Kryo 编码误当纯文本。沿用当前单 Redis 部署与旧键名，不迁移数据库或协议；校验失败可以留下无消息的预留 ID，重试仍复用。
- 独立地区解析器仅同步读取缓存。内网、回环、链路本地及无效地址跳过查询；公网缓存未命中时使用有界专用线程池预热，同 IP 合并，成功缓存一小时、失败退避一分钟。队列满时放弃本次预热，不能回退到请求线程执行。首次消息使用未知地区；缓存完成后仅供后续消息使用，不修改已发送实体。
- HTTP 发送协议不变。服务端广播仅在持久化后发出，因此匹配同账号/clientMessageId 的正式实体即可确认发送；HTTP 后续失败不覆盖已确认状态。保持本地渲染 key、撤回墓碑、草稿和账号取消边界。
- 不引入依赖，不改变主题、外壳、排版或连接所有权。共享消息内核应用于全部主题及明暗模式。
- 开发环境只有显式配置 `VITE_DEV_API_TARGET` 才启用 `/api` 与 `/ws/` 同源代理；WebSocket 单独指定 `VITE_DEV_WS_TARGET`，代理将 `/ws/` 改写为 Netty 根路径。前端 API 根地址指向本地 Vite origin。默认线上地址与生产发布行为不变，避免把启动本地服务误当成前端已经切到本地。

## 替代方案

不取消分布式锁或持久化来换取响应速度；不缓存账号封禁、禁言与身份资料；不在请求线程上使用饱和后 CallerRuns 的公共线程池进行定位。不引入数据库发送键迁移或 Redis 集群方案。

## 验证

单测覆盖原子 ID 预留、幂等、失败与撤回、定位冷缓存/合并/退避/拒绝及私网跳过；前端覆盖广播先到、HTTP 先到、迟到失败和账号隔离。浏览器发送流程覆盖注册主题 × 明暗 × 桌面/375/390；执行 npm run check。真实联调耗时、验证范围与限制记录于 docs/audits/chat-send-latency.md，不把 mock 数字当真实服务性能。
