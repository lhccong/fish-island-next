# ADR-061：像素首领挑战与逐层试炼

状态：采用。日期：2026-11-14。

## 原因

原挑战面板将 Boss 与爬塔隐藏在分类选择中，战斗缺少站位、生命进度与回合反馈；爬塔尚缺旧版楼层预览和排行。用户要求宝可梦式像素对战视觉与完整入口。

## 决策与影响

- 四类宠物排行统一展示服务端 userAvatar，伙伴/首领/排位榜保留 petUrl/petAvatar 为宠物小像。domain 明确保留头像字段，infrastructure 复用安全图片 URL 校验；feature 的统一排行行管理头像加载/失败回退，不逐行补发用户资料请求。名次、头像、身份、成绩与操作分列，手机重排操作，长昵称和组合字符在各自文本行内裁切，避免越界。前三名使用既有语义色轻量强调，所有主题和明暗模式复用，不改变排行协议、排序或业务状态。

- 保留 domain → infrastructure → feature → app 的既有边界，在 PetPort 补充楼层预览与爬塔排行；沿用旧版 `/api/tower/floor`、`/api/tower/ranking`、进度、挑战及 Boss 协议，不新增依赖。
- 营地提供 Boss、爬塔直达入口，原挑战分类继续可用。独立 Boss、塔与排行组件拥有各自读取状态；楼层预览与排行榜按需读取，支持取消和重试。
- 入口文案为“开始挑战”与“开始试炼”。各自生命仪表下方以一排六个小方格展示本人及接口返回的宠物对手装备，复用 ItemIcon 的 compact 呈现与实际强化等级；Boss 无装备栏，不伪造对手物品。明细读取既有 equippedItems，缺失与明确空装备区分呈现。暴击、闪避、格挡、连击和吸血分别使用金色爆点、蓝色残影、护盾、双斩痕与绿色回血光圈，由服务端标记触发；减少动态效果时保留静态文字和配色。
- 战斗以原创像素场景、前后站位、HP 仪表、冲刺、受击和伤害反馈呈现。角色、血条和装备始终位于同一侧且上下邻接，我方左侧、对手右侧，仪表明确标注归属；手机保留左右两组，装备改为三列小格。动画只回放服务端回合，胜负优先使用显式结算，不推算奖励、不提供未接入的技能或物品按钮。空回合禁止直接重试提交，须先返回列表核对状态。
- Boss 生命使用真实 currentHealth/maxHealth，零生命不能回退成满血。塔的自身生命预览在 domain 兼容当前后端 BattleStatsVO.fromPet 的“等级 × 100 + 装备生命”规则，回合剩余值始终使用服务端结果；不以首回合剩余生命冒充初始上限。后端该规则变化须同步适配。
- 塔战结束可主动刷新并继续下一层；刷新必须先读取新进度，不在客户端自行增加层数。主题和模式不参与请求依赖，不重挂载正在回放的战斗。
- 仅挑战相关弹窗采用像素呈现变体，继续复用 shared/ui/Dialog、Select、Button、reserved ScrollArea。像素场景颜色由 pet 局部明暗 token 提供，功能控件使用主题动作色；不扩大皮肤导入白名单。手机按 760px 重排并保留 44px 触控及安全区。

## 替代方案

拒绝复制旧 Ant Design 战斗页：违反组件与依赖约束，且无法解决移动端与双模式一致性。无需引入游戏引擎或持续粒子循环，CSS/SVG 足以表达服务端回合。

## 验证方式

执行 npm run check；单元验证新协议、零血量与显式胜负优先级。浏览器使用合成接口覆盖全部注册主题 × 明暗 × 1440/375/390，验证 Boss 与塔入口、楼层预览、排行、真实滚动、开始/跳过/重播、失败恢复、空回合保护、继续下一层及切换外观不追加业务请求。截图目视检查桌面与手机构图。真实账号/后端联调情况在交付记录中单独说明。
