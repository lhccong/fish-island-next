# ADR-101 界面字号本机偏好

状态：已采用。日期：2026-11-19。

## 原因与方案

网站设置增加较小（90%）、标准（100%）、较大（110%）、特大（120%）四档界面字号。沿用网站设置的保存与恢复默认流程，将字号与标签页偏好一次写入同一条本地记录。旧记录与无效字号使用标准档。保存字号时仅在图标地址改变时验证图片，避免已有图标失效阻止字号调整。两个网站设置入口复用同一表单。

appearance 持有本机偏好，app 将字号倍率作用于文档根字号。界面排版使用 `rem` 及相对行高，让各级文字和 Portal 同步响应。保留已接入主题、明暗模式、图片、布局尺寸、触控面积和滚动区留白。原有 16px 移动输入字号作为下限。阅读器正文继续使用阅读偏好中的独立字号。字号变化只更新 CSS 和本机存储，聊天沿用虚拟行的尺寸测量，无新增请求、重连或草稿订阅。

## 影响与替代方案

只调整根字号无法覆盖旧的固定像素文字，因此同步迁移界面排版单位，标准档在浏览器默认 16px 字号下保持既有文字层级。整页缩放会影响图标、触控区域和视口布局。组件逐一订阅字号会扩大聊天渲染范围。根字号与相对单位可共用现有样式管线，无需追加依赖或开放皮肤导入 token。

## 验证

执行 `npm run check`。按注册主题 × 明亮/暗夜 × 桌面/375px/390px 验证网站设置的选择、保存、刷新、恢复默认、焦点、滑轨及无溢出，并检查字号对外壳及业务正文的作用。覆盖本地存储失败、设置未保存、热榜加载/空/失败/成功，以及聊天草稿、请求和连接在保存字号后保持稳定。
