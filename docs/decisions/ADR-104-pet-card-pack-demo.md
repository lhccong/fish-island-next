# ADR-104：宠物卡包试玩

状态：采用。日期：2026-11-22。

## 目标与决策

- 「海岛初遇」和「三国群英」各收录五十张卡，普通至闪耀每档十张。两个卡包复用同一本机存档，按北京时间共享每日两次领取额度。各包独立抽取五张，每种卡包的首次开包第五张为保底闪耀。其余卡位各档概率依次为 46%、28%、16%、8%、2%，同档等概率。
- 三国图集按蜀汉、曹魏、东吴、汉末群雄、桃园同袍五组绘制。领取时记录卡包种类，刷新恢复当前拆包，旧存档中的待拆包或结果沿用海岛初遇。卡包选择器复用共享 Select，按所选卡包浏览卡池，同一展示柜可上架两套卡片。
- 卡面由五张各十格的独立图集承载，四组新增插画分别为珊瑚海湾、苔光林地、雪湾、浮云群岛。图集仅用于呈现，四组新卡和原有卡均从同一个卡池抽出。
- 每种卡仅收藏一张。同一包和跨包重复均自动按品质折算 5、10、20、40、80 试玩积分。展示柜三席，收藏后可随时上架或撤下。
- domain/pet 定义纯规则，infrastructure/pet 用已有 Dexie 依赖在 IndexedDB 事务内提交领取、结算与展示操作。app 注入独立端口，按后端和账号隔离，开发试玩使用独立存档。跨标签页订阅同一存档。领取后可跨日继续拆，刷新可续看最近一次尚未确认的开包结果。积分仅用于试玩，未来服务端接入需由后端结算和持久化。
- 营地全页和现有独立小窗共用卡包入口。开发服务器另提供 `/pet/cards-demo` 即开即玩。弹窗固定标题和操作区，正文使用 reserved ScrollArea。主题控件沿用现有变量，卡面统一使用原创插画与既有品质语义色。拆封、翻转和闪耀效果使用 CSS，尊重减少动态效果设置。
- 每种卡的攻击、防御、生命、速度基础属性及数值沿用原卡池，供后续宠物玩法使用。未来玩家对战中，双方各出一张牌，亮牌后结算普通卡的攻击或闪避。精良、史诗、传说和闪耀的效果只在打出后的下一回合生效。精良统一在下一回合开始时回复最大生命的 6%。回合型增益和护盾限定在下一回合，首次事件按下一回合内的首次发生判断，低血量条件在下一回合开始时判定。闪避是普通卡的动作，原有闪避类效果改为暴击、护盾、增伤、减伤或命中加成。极光灵狐在下一回合首次命中时必定暴击。卡面文案由效果数据生成，展示柜独立呈现宠物属性加成与对战效果预览。本轮交付卡片数据和前端呈现，正式结算随玩家对战实现。闪耀揭晓位于滚动视口上方的中央独立演出层，逐张及批量翻牌均触发。点击继续退出演出，减少动态效果时呈现静态揭晓。
- 根据用户参考图组织卡面和密封包外观。卡面使用品质金属渐变镶边、通栏插画和同色衬底。卡名与 HP 叠在画面上方，品质和被动、属性位于下方，密封包保留蓝色饰边。图鉴可以预览未收藏卡的插画，卡片下方保留未收藏状态。同一网格卡面等高，长说明可以完整换行。
- 底部提供恢复初始状态，经确认后在同一笔本机事务清除当前试玩存档的领取次数、待拆包、结算结果、收藏、展示和试玩积分。卡包序号继续递增，其他标签页尚未处理的旧卡包操作无法修改重置后的卡包。

## 替代方案

- 接入正式积分及奖池需要后端事务和账号资产规则，本轮以前端试玩验证开包体验。
- 用逐项写入的本地存储会在跨标签页领取时产生竞争，已有 IndexedDB 依赖可实现单事务结算。
- 使用三维引擎会增加启动资源和对 WebGL 的要求，二维包装和卡片已能呈现本轮动作。
- 仅保留被动说明需要后续对战重复录入或解析文案。卡片目录直接保存结构化对战效果，界面据此显示描述。

## 验证

在单元测试验证跨日、同包去重、积分、展示规则、亮牌动作与下一回合效果、精良回血，以及基础属性和效果的独立性。按内置主题 × 明暗 × 1440px、375px、390px 验证领取、开包、查看结果、卡面等高、展示柜预览、上架、退出、恢复、键盘和触屏，并注入存储故障验证重试。交付前运行 `npm run check`。
