# ADR-036 公共群历史首次加载与上翻

日期：2026-11-12。采用。

## 原因与协议

补齐打开聊天室时的 HTTP 历史加载。沿用旧版 chatController 和 Chat 页实际协议：POST `/api/chat/message/page/vo`，公共群 `roomId:-1`，`pageSize:50`、`sortField:'createTime'`、`sortOrder:'desc'`；首批 `current:1`，后续传 `messageId` 游标。响应为 `data.records[].messageWrapper.message`，复用实时消息解码，不猜测额外 DTO。游标保留字符串，避免长整数精度损失。

## 决策与影响

### 2026-11-13：从其他菜单返回时刷新

聊天消息区从无订阅到激活时重置历史游标、去重集合和加载反馈，再请求最新 50 条；保留已有消息实体、撤回墓碑、发送状态与账号草稿。离开时取消请求并拒收迟到响应。相比清空页面重新登录或重建账号连接，此方案保持状态与单一连接所有权；相比沿用旧游标，可以获取离开期间的最新消息。请求失败保留旧内容并允许显式重试。主题和模式不参与激活依赖。

进入消息区同时请求现有连接立即重试：已连接或正在握手时复用，断线时跳过当前退避等待，离线仍暂停、认证失效仍停止。常规断线继续沿用 ADR-035 的自动重连策略。最新一页刷新不代表断线期间完整补拉。验证覆盖反复返回、取消与迟到响应、失败重试、已达窗口上限、连接复用及全部主题/模式/视口。

本次合成接口验收覆盖 WPS、微信、企业微信、飞书、钉钉 × 明亮/暗夜 × 桌面 1280px、手机 375px/390px：加载、空态、失败重试、返回后请求首批、去重、断连恢复及草稿保留，配合无横向溢出与消息可见性断言。手机以触屏点击真实返回和菜单入口。登录后的路由落点曾导致一项测试未进入聊天，测试改为等待登录导航结束并显式进入聊天后复测通过。截图已抽查桌面和两种手机宽度，临时截图及追踪在验收后删除。真实服务端断网、软键盘及长时性能未验证。

- domain/chat 的历史端口返回 ReceivedMessage；infrastructure/chat 持有 HTTP、鉴权、取消及 DTO 适配；独立 history-controller 持有请求/游标，realtime-controller 组合同一个归一化消息模型；app 注入。首次打开时请求，刷新重新请求；账号内路由返回保留消息实体并重新请求最新页，未完成请求在离开时取消。主题/模式/头像偏好不参与请求依赖。
- 单一历史请求在途，16ms 实时队列先提交再合并 HTTP 结果；按 ID 去重，撤回墓碑优先于历史正文。历史结果不能覆盖已收到的同 ID 实时实体。服务端短页、空页、重复游标或没有新增历史 ID 时停止；错误保留已有消息、显式重试，不自动循环失败请求。
- shared/ui/InfiniteScroll 增加 start/end 边界变体，使用实际共享 ScrollArea 视口；Virtuoso 稳定 Header 承载历史加载状态，firstItemIndex 维护向上追加的锚点。首批靠底显示；回看不跳底，短列表自动按需续读。无页码或加载更多按钮。
- 沿用 ADR-035 的当前窗口 1000 条上限。本阶段窗口到达上限时停止继续查询，并明确显示“已达到当前消息窗口上限（1000条）”，不能显示“已全部加载”。这是阶段性受限历史浏览：暂不实现双向逐出/再加载页缓存。相较无限堆积，限制内存；相较双向缓存，避免在本次首次加载修复中引入未经验证的缓存和锚点状态机。未来全量历史回看需另行引入页级双向窗口并验证，不宣称支持无限历史。
- 当前接口只确认向旧消息读取，不提供断线期间 seq/cursor 续传，继续保留“断线期间可能漏收”提示，不宣称断线无丢失。不新增依赖或发送能力。

## 验证

### 2026-11-13：恢复页面后的定位与滚动协调

消息窗口淘汰和变高行测量期间，消息区额外的 ResizeObserver 直接滚到底部会与 Virtuoso 的锚点补偿、定位滚动争抢位置。移除该观察器的滚动写入，由 Virtuoso 统一处理尺寸测量与跟随；滚动跟随作为消息列表局部状态，回看或定位时关闭，滚回底部、主动发送或点击最新消息时开启。向 Virtuoso 传入明确的 false/auto，而非始终存在的回调：当前版本的部分尺寸变化分支只检查 followOutput 是否为 false，不读取回调返回值。相比增加定位重试或反复 scrollTo，此方案避免叠加滚动控制器，不改变消息窗口、请求、账号草稿与主题状态。回归覆盖已挂载列表积累超过 1000 条入站消息、@我与引用定位、逐帧滚动稳定性、新消息不打断回看以及返回最新消息；真实设备长时间休眠仍需另行验证。

### 2026-11-13：兼容系统消息游标

福袋、开奖等系统消息使用 UUID，业务消息 ID 并非数据库主键，也不保证按时间递增。后端 `messageId` 改为字符串，先在同一房间精确定位游标记录，再按 `(createTime, id)` 向前查询；首批与续页使用相同的时间降序、主键降序。找不到游标时显式报错供重试，不能误报已全部加载。保留历史 UUID 和数字字符串，不迁移已有记录或改变消息去重标识。相比强制改用数字 ID，此方案兼容存量及其他系统消息；相比将数据库主键透传为新协议字段，不增加客户端协议。验证覆盖 UUID/长数字、同时间记录、混合类型分页、无效游标及前端上滑锚点。

单元测试覆盖 HTTP 参数与鉴权、解码、错误/取消、历史/实时重叠、先撤回后历史、请求串行、重复/空页停止、账号重置丢弃迟到响应与窗口上限。浏览器按全部主题 × 明暗 × 桌面/375/390 验证首次请求、加载/空/失败/成功、上翻保持锚点、续读失败重试、去重、撤回、草稿及主题/模式不触发请求。运行 npm run check。真实后端、长时间运行与性能 p95 未测须披露。
