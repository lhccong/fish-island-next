# ADR-089 聊天图片重挂载与测量稳定性

日期：2026-11-16。状态：采用。

## 原因

视频反馈聊天列表上下抖动。回归发现图文历史上翻的逐帧锚点偏移约 197px；图片的原始比例仅存在消息行局部 state，虚拟行离屏卸载后丢失，再进入时重复从 214×160.5 占位切换到实际尺寸，触发虚拟列表重复测量与锚点补偿。原有稳定性测试等待滚动稳定后才采样，不能覆盖重挂载的中间布局。

## 决策与影响

chat 的账号级 Provider 持有有界图片比例缓存，最多 1000 条，只在内存保存 URL 与有效原始比例，账号或控制器变化重新创建，不写存储、不新增网络请求或图片预加载。消息图片初次展示仍使用原占位、成功后按真实比例收紧；再次挂载从已知比例直接布局，加载、失败及重试保留尺寸，继续支持按需显示、折叠、预览与原图配色。缓存不订阅消息、草稿或主题，不持有图片 DOM 和二进制数据。

消息虚拟列表在 ResizeObserver 回调中直接交给 Virtuoso 测量，避免额外推迟一帧才补偿已变化的行高。滚动与锚点仍归 Virtuoso 所有，不叠加业务 ResizeObserver 的 scrollTop 写入，不以固定图片框或取消虚拟化掩盖问题；若验证发现其他原因，应在同一变更更新本决策。

使用已安装版本的公开选项 `skipAnimationFrameInResizeObserver`。[Virtuoso 官方说明](https://virtuoso.dev/react-virtuoso/api-reference/virtuoso/#skipanimationframeinresizeobserver)明确指出该设置减少闪烁，但测量过程中布局变化可能产生良性的 `ResizeObserver loop completed with undelivered notifications` 浏览器通知。开发验证确实出现此提示；保留原始通知，不加入全局异常屏蔽或改写浏览器 API。验收按实际绘制帧的锚点与停止滚动后的位移判定，不把该通知等同于业务异常，也不宣称控制台零提示。

## 替代方案

不恢复固定 4:3 图片框，避免破坏已确认的按真实比例收紧布局；不使用全局无界缓存或 localStorage，避免跨账号和内存增长；不通过反复强制跳底、延迟后再定位或隐藏内容消除截图中的抖动。

## 验证

先运行失败回归保留修复前证据，再验证宽图/长图/图文混排、慢加载/失败/重试、行卸载重挂载、真实滚动与停留、新消息不抢回看、上翻分页锚点和预览关闭焦点。重挂载采样包含加载与成功之间的布局，分页按绘制帧采样。覆盖全部注册主题 × 明暗 × 桌面/375px/390px，执行 npm run check；记录发布/开发模式及未验证的真机与性能项目，临时产物提取结论后清理。

## 执行结果

2026-11-17 触底修正：触底阈值收紧为 1px。数据提交、`totalListHeightChanged` 和真实视口尺寸变化共用一次绘制帧，仅在仍有跟随意图且实际剩余距离大于 1px 时，通过 Virtuoso 的 `scrollTo` 到实际内容末端；发送及“查看最新”也复用此入口。保留库内消息行测量，关闭 `followOutput` 的估算索引跟随，避免估算位置与实际 DOM 高度的偏差及两条路径争抢底部。图片懒加载/失败等延后测量与软键盘/输入区缩放均沿用同一调度，没有直接写入 scrollTop 或定时轮询跳底。

达到 1000 条后总条数及总高度可能不变，但末项已更换。首项索引变化到 Virtuoso 报告滚动结束之间的锚点补偿不视作用户上翻；原生向上滚轮、触摸、向上键盘导航及滑轨拖动仍同步取消跟随，向下回到底部附近才恢复。回看时从实际滚动位置保留首条可见消息 ID 和相对位置，只有窗口淘汰首项时激活锚点补偿，经同一帧内的 `scrollBy` 修正偏移；新用户操作或主动发送取消旧补偿，不保存消息正文、不增加订阅或请求。普通历史上翻继续由 Virtuoso 管理；新增的视口 ResizeObserver 只发出尺寸变化通知，卸载释放观察器、监听器和待执行帧。不采用仅按消息条数变化跟随或延迟固定毫秒再跳底的方案，前者遗漏行高变化与窗口淘汰，后者会争抢用户操作。

新增浏览器回归对连续收发、图片 loading/error/retry/success 后的剩余距离作 ≤1px 断言，并覆盖 1000 条窗口淘汰、回看锚点及查看最新。验证结果随本次交付记录。

2026-11-16，基于 `0a97f71` 的工作区修复，Windows 本机、Playwright 1.65.0 附带 Chromium。修复前开发版历史逐帧锚点偏移为 196.59375px；宽图重挂载时尺寸偏差为 131.96875px。仅保留图片比例而不提前测量时，历史锚点测试仍失败，确认两处修复均有必要。

`npm run check` 通过：106 个测试文件、432 个单测、格式/lint/类型和生产构建成功；保留既有大包和鱼小圈静态/动态导入构建警告。生产构建经独立 `vite preview` 验收：`chat-image-history`、`chat-image-scroll-stability`、`chat-media` 共 126 项通过，覆盖摸鱼岛、摸鱼岛像素风、WPS、微信、企业微信、飞书、钉钉 × 明亮/暗夜 × 1280×720、375×812、390×844。验证初始空列表、慢图片 loading、失败重试、成功、图文历史上翻、新消息不抢回看、头像显隐、草稿/连接保持与无横向溢出。

摸鱼岛明亮下额外 24 项生产回归通过，覆盖上述三视口及视频对应的 1282×624；包含图片折叠/展开及预览焦点、混合红包历史停止滚动后的稳定性、手机连续触摸拖动与长按取消/菜单操作。已知宽图及长图重挂载的宽高偏差均按 ≤1px 断言，滚动停留及新消息到达位移按 ≤1px 断言；历史分页阅读锚点按绘制帧 <5px 断言。抽查经典桌面、390px 暗夜与视频尺寸截图。

合成账号和拦截接口仅用于验证，未操作真实聊天。未验证真机 Safari/微信内置浏览器、软键盘、线上接口、30 分钟内存趋势、FPS/掉帧、长任务或输入 p95；上述结果是功能及布局回归，不是完整性能预算达标报告。图片缓存容量与非法比例有单测覆盖。全部临时结果、截图与 trace 在独立目录 `C:/Users/SEASUN/AppData/Local/Temp/fish-jitter-20261116-1574` 中生成；提取结论后核对了绝对路径，尝试逐文件及空目录清理，但自动审批策略返回 `blocked by policy`，删除命令未执行，因此 baseline、cache-only、first-fix、mobile-smoke、production-matrix、production-regression、repro、repro2 仍保留，需手动删除此任务目录。预先存在的 dist 与其他任务的产物保留。
