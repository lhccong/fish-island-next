# ADR-022 鱼小圈操作与互动通知

状态：采用。日期：2026-11-12。

原因：封面下的文字工具栏占用空间，缺少旧版互动消息入口。

方案：全部动态、我的鱼小圈、刷新、通知和发布使用封面右上角的图标按钮，保留可访问名称与选中状态。通知采用微信式紧凑列表，复用共享 Dialog 与 ScrollArea；手机使用安全区域内的可滚动面板。独立通知组件拥有分页、已读与删除状态，动态详情复用现有卡片与评论交互。

协议：FishCirclePort 增加 reminders、reminderAction、detail；infrastructure 校验旧版 event_remind/my/list/page、batch/set/read、batch/delete 和 moments/detail 的响应。列表每页 10 条，按 createTime descend；state=1 表示已读，sourceType=4 表示动态。未读提示仅统计当前分页，禁止宣称全站未读总数。未迁移的帖子仅展示通知正文并明确提示详情不可用，不导航到不存在的页面。静默轮询暂不迁移，打开和主动刷新时读取，避免隐藏页周期请求。

影响：不新增依赖，不改变外壳或主题协议，全部主题与双模式复用语义颜色。

替代：复制旧版抽屉会带入 Ant Design 和巨型页面状态；新建全局通知 store 暂无跨页面消费需求。

验证：HTTP 解码与协议单测；全部注册主题 × 明暗模式 × 375、390、桌面，验证加载、空、错误、成功、分页、标记已读、删除、详情、关闭与发布入口；运行 npm run check。

详情呈现补充（按用户纠正更新）：关联动态通知点击后关闭通知浮层，在工作台主内容区切换成微信式详情，不使用 Dialog、Portal、遮罩或 fixed 覆盖；不等待标记已读成功。CircleFeed 持有详情选择，通过已有 contentScroll=false 布局契约提供独立的列表和详情 ScrollArea。列表保持挂载但隐藏，保留数据、评论草稿及滚动位置；返回恢复原列表，并聚焦消息通知入口，不重新请求列表。详情页内固定标题和返回入口，手机占满主内容区并保留安全区域。MomentCard 的 detail 变体复用同一点赞、评论、媒体预览和权限逻辑。替代方案是详情弹窗，但不符合用户要求；卸载列表则会丢失草稿和滚动位置。验证覆盖全部主题、双模式、三种视口的页面内切换/返回、失败重试、媒体预览、滚动、状态保留和无重复列表请求。

ScrollArea 允许通过 `--scroll-area-reserved-gutter` 明确指定预留宽度，详情使用桌面 24px、手机 20px；其他现有调用保持原间距。标记已读期间通知条目继续允许浏览，避免返回时焦点落在禁用控件上。

评论通知定位：旧 EventRemindVO 只有 senderId、sourceContent、createTime 与动态 sourceId，没有独立评论编号。domain 保留发送者编号；feature 用发送者编号（缺失时姓名）、完整正文和图片匹配评论，多条候选再用时间消歧。按现有评论分页逐页查找，自动展开目标的祖先回复，滚动到目标并保留语义高亮与文字标识；找不到或无法唯一匹配时明确提示，不随意高亮相似评论。一次自动查找最多读取 200 条根评论，达到上限后由用户继续；请求错误可重试，离开详情取消未完成请求。替代方案是按通知正文模糊查找第一条，但会定位错误；增加评论编号需后端协议支持，当前不虚构接口。主题切换不重新定位、不触发额外查找。验证覆盖首屏、后续页、嵌套回复、同文消歧、缺失、失败重试和离开取消。

呈现补充：定位标签按内容收紧；互动通知采用对齐的头像、姓名/时间、互动说明和正文，复用主题语义颜色与 reserved gutter；保留触屏、键盘焦点、加载、空和失败反馈。
