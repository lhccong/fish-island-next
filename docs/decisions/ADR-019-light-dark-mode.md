# ADR-019：独立的明亮与暗夜模式

状态：已采用。日期：2026-11-12。

## 原因与决策

当前五种主题只提供明亮配色；用户要求整个系统支持两种模式，暗夜基础背景为 `#191A1C`。新增独立 `colorMode: light | dark`，与 `skinId` 分开持久化；默认明亮模式，主题弹窗和初始化页均提供模式选择。切换不重挂载业务、不重取数据、不丢失草稿和游戏进度。

`skins/builtin` 提供纯配色组合函数，统一生成“主题 × 模式”的十二个内置 token；`features/appearance` 拥有选择状态，app 的 SkinProvider 应用组合结果与根节点 `data-color-mode`。其余语义变量由全局模式样式提供，覆盖热榜、鱼小圈、登录与授权页、WPS 外壳、游戏及通用控件。原生控件通过 `color-scheme` 适配；首屏脚本读取已保存模式，避免暗夜刷新时先显示明亮背景。

暗夜采用层级深灰背景和明亮文字，保留各平台强调色身份，并分别提供可读的强调文字和按钮背景。预览使用与实际页面相同的组合函数。图片、封面、游戏插画不反色；不新增 CSS 导入权限。

## 影响与替代方案

不增加依赖，不改变外壳映射、业务状态或第三方皮肤白名单。相比新增一个独立“黑色主题”，模式组合允许五种主题各自保留颜色和布局；相比整页 invert 滤镜，语义配色不破坏图片与状态含义。

ADR-009 授权页仍独立于工作台品牌配色，但其局部语义变量必须响应明亮/暗夜模式，替代此前仅固定明亮的配色约定。

## 验证

执行 `npm run check`。单元测试覆盖模式组合、强调文字和按钮的对比度、偏好恢复与存储不可用。浏览器覆盖五种主题 × 两种模式 × 桌面/375px/390px，验证热榜、登录弹窗、鱼小圈、游戏目录与模拟器、初始化页、授权页，以及加载/空/错误状态、刷新恢复、输入草稿与游戏状态保留；记录截图及实际未验证项。
