# ADR-015：微信侧栏与评论满页修复

状态：采用。日期：2026-11-11。

## 原因与选择

按用户明确的最终范围，只有左侧「发现」功能栏采用微信样式：扁平选中行、功能图标和账号缩略图。左侧仅保留朋友圈入口，移除重复的「我的鱼小圈」项；个人视图仍通过右侧切换与封面头像进入。热榜与鱼小圈的导航图标交换为 Camera 与 Compass，路由与名称不变。右侧保持 ADR-012 已交付的鱼小圈样式，包括默认账号封面、圆头像、圆角动态卡片、暖橙置顶、桌面双栏置顶列表；手机仍为单栏与折叠置顶列表。不能将微信扁平动态流套到右侧。

feature 内部由 CircleFeed 提供 header/content 区域，Workspace 注入只读导航，app 仍组装外壳与服务。HTTP 与弹窗状态归原有功能组件，草稿独立管理。未新增依赖。

## 评论问题与修复

旧 page 解码直接使用 records.map(decode)，数组 index 被传入 comment 的 depth 参数，导致第九条带回复、或第十条普通评论误报层级异常。分页仅传条目参数；公开 comment 解码接口固定单参数，私有递归单独拥有真实深度。保留异常嵌套保护，不通过删除校验掩盖问题。

## 验证

单元先复现 10 条顶级评论均带子回复的异常，再验证修复；覆盖满页与字符串总数、真实嵌套限制。浏览器覆盖 15 条评论的首/末页、末条子回复和错误重试，以及桌面、375px/390px 的加载/空/失败、置顶定位、封面、导航图标、发布/评论和弹窗流程；使用合成数据。执行 npm run check。
