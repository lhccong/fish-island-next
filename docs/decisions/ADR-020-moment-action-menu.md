# ADR-020：动态操作使用锚定菜单

状态：已采用。日期：2026-11-12。

## 原因与决定

“更多动态操作”原先打开居中 Dialog，遮挡动态上下文。改用紧贴触发按钮、右对齐的非模态菜单，不显示遮罩、标题或说明。操作顺序为抽奖/打赏、置顶、修改、删除；现有权限及后续编辑、确认流程保持不变。

按需引入 MIT 许可的 `@radix-ui/react-dropdown-menu`，属于既有 Radix Primitives 技术栈。由 shared/ui/DropdownMenu 封装 Portal、碰撞避让、键盘导航、外部点击关闭与焦点恢复，业务组件只传操作项。不增加新的 UI 框架。菜单随鱼小圈懒加载，构建时检查异步块体积。

## 替代方案与影响

继续使用 Dialog 无法满足锚定菜单需求；手写绝对定位菜单需要自行维护滚动裁剪、视口碰撞与键盘行为，因此采用既有技术栈的标准原语。菜单使用当前模式的语义颜色与阴影，手机操作项至少 44px 高，桌面使用紧凑行高。Portal 避免动态卡片和滚动区裁剪，关闭后返回稳定的更多按钮；打开后续 Dialog 时由 Dialog 的 returnFocusRef 恢复焦点。

## 验证

执行 `npm run check`；通过 Playwright 验证注册表全部主题 × 明亮/暗夜 × 桌面、375px、390px，覆盖菜单边界、键盘、外部关闭、编辑后焦点、置顶及失败反馈、动态 loading/empty/error/success。测试仅使用合成账号与动态。
