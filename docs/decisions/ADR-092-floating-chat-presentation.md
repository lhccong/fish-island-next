# ADR-092 聊天小窗气泡与 Excel 模式

状态：采用。日期：2026-11-16。

## 原因与决策

参考旧摸鱼岛 FloatingChat 的气泡/Excel 切换，在现有聊天小窗标题栏提供 shared/ui/Select 模式选择。ChatWindowProvider 按账号独立保存 conversation/worksheet 呈现，默认气泡；收起、跨菜单、关闭后再次开启仍保留本次会话选择，账号释放后重置。不改变全局主题及明暗模式，也不改写完整聊天由 app 注入的呈现。

Excel 模式复用 ADR-052 的 MessageStream、MessageRow、ChatComposer 和工作表标签，以行号、列标题、消息单元格及公式栏式输入表达真实聊天。可访问窗口标题使用群名.xlsx — Excel，视觉标题为 Excel；小窗独立采用时间/昵称/正文三列，长内容换行，完整 WPS 工作表保持原有窄容器重排。没有电子表格计算、编辑或独立连接。所有配色使用明暗语义 token；小窗不应用经典/像素聊天装饰。

shared/ui/FloatingWindow 增加可选 headerAction/titleContent 纯表现插槽及 standalone/worksheet 呈现，选择器与拖动、收起、最大化和关闭分开，保留标题与操作空间；标题栏样式只作用于直接操作按钮，不覆盖 Select 的触发器及展开面板。手机保持全屏、安全区和 44px 触控入口。模式变化只更新呈现 props，列表、滚动容器、输入 DOM、账号草稿及请求生命周期保持挂载。

## 影响与替代方案

标题栏模式入口按用户反馈改为单个图标；shared/ui/Select 的可选 triggerIcon 只改变触发器呈现，保留组合框、隐藏的当前值、提示、焦点、44px 命中区和原有选项面板，默认选择器不变。

紧凑工作表以 Virtuoso 默认的帧调度批量测量密集单元格，避免切换和批量入站时同步 ResizeObserver 产生循环通知；普通聊天和 WPS 完整工作表保留 ADR-089 的同步锚点补偿。只改变测量调度，不新增外部滚动写入或观察器；验证切换、图片展开、首末可达及历史锚点。

紧凑消息区使用同一 ScrollArea 的 reserved gutter，将既有 24px/20px 外侧留白移至实际滚动视口内部，保留正文宽度并使滑轨与单元格、焦点环分开。手机隐藏滑轨而保留空间；用布局断言验证正文到视口末端的固定间距。

根据用户提供的旧版截图，小窗 Excel 使用独立的紧凑呈现：绿色标题和功能区、A/B/C 对应时间/昵称/正文、细网格、消息记录标签，隐藏头像、称号、行操作栏和重复站点页脚，消息操作仍通过右键/键盘/手机长按菜单访问。手机保留三列，通过固定时间/昵称宽度及正文换行维持可读性；字体与输入、控件触控高度按当前规范提升，不照搬旧版过小触控尺寸。图片默认显示可展开的“[图片]”单元格，复用现有图片加载与预览；这只改变小窗呈现，不改全局图片偏好。局部 Excel 明暗语义 token 存放于 app 样式，全部主题共用，暗夜以 #191A1C 为底。

新增 /chat/mini 鉴权路由和新标签页链接；app 组合独立呈现 Provider，默认 Excel，仍注入同一聊天端口、账号连接与草稿。每个标签页使用各自既有账号连接，不额外创建同页连接；不通过 URL、源码或新存储传递凭证。独立页面复用 ChatWorkspace 和 FloatingWindow 的全视口呈现，隐藏工作台导航、拖动/缩放及收起入口，关闭返回 /chat。未记住登录的独立标签页按既有会话恢复规则登录。

验证发现存量消息菜单层级低于悬浮窗，现将共享 ContextMenu/DropdownMenu 统一置于浮窗和 Dialog 上方（90），以支持真实点击、触屏和焦点恢复，不使用强制点击绕过遮挡。

覆盖 ADR-084 中“小窗固定普通会话”的限制，其他依赖方向、状态及业务协议不变。未复制旧版 FloatingChat 或另建表格列表，避免历史、消息操作与发送状态分叉；未把 Excel 绑定 WPS 主题，确保所有主题都能独立选择小窗模式。没有新增依赖或持久化端口。

## 验证方式

执行 npm run check；全部注册主题 × 明亮/暗夜 × 桌面/375px/390px，验证模式选择、键盘/Esc/焦点返回、触屏、无横向溢出、加载/空/历史错误恢复、消息接收与发送失败重试、引用及图片、滚动首末可达、小窗收起恢复与返回完整聊天。断言草稿及列表 DOM 身份、请求与连接计数，检查主题切换不改变小窗模式。查看实际截图后清理本次临时产物，记录实测范围及限制。

## 验收记录（2026-11-16）

Windows / Playwright Chromium，基线 d8c92f9 上的工作区变更，独立 Vite 生产快照；仅使用合成账号、HTTP/WS 及消息夹具。覆盖注册表全部七个主题：moyu-island、pixel-island、wps、wechat、wecom、feishu、dingtalk × light/dark × 1280×720、375×812、390×844。

最终专项 93 项中 92 项直接通过；唯一失败是新增历史夹具错误模拟为页码请求，已按实际 messageId 游标协议修正。历史专项随后在三个视口独立重跑，3 项全部通过，未为夹具修改生产通信代码。其余 90 项覆盖小窗/独立页的加载、空、读取失败重试、接收、发送失败重试、引用、图片展开、触屏和键盘菜单、Esc 与焦点归还、图标中心及隐藏文字宽度、桌面最大化/还原、收起恢复、返回完整聊天、鉴权及新标签页会话恢复。切换模式及全部主题明暗时保留草稿、编辑器与滚动容器 DOM，不增加同页连接及历史请求。历史补测覆盖两页连续向上加载、失败保留内容/锚点、重试、空页结束和模式往返。

桌面主动显示消息滑轨，手机检查滑轨隐藏及真实触屏滚动；固定 gutter 布局断言要求单元格末端到实际视口末端至少桌面 24px、手机 20px，消息区、输入区、窗口及行均无横向溢出。检查了明暗、桌面和手机的实际截图，模式入口仅保留单个图标，没有白色按钮框和残留文字。临时截图、trace、测试结果、独立构建和配置在提取结论后删除；已有目录和其他任务产物保留。

全仓 npm run check 通过（格式、ESLint、TypeScript、109 组 / 451 项单元测试、生产构建）；既有大块体积和混合动态导入提示不作为本次性能达标结论。未验证真实后端/真实账号、真机软键盘、Safari/Firefox，以及聊天输入 p95、长任务、长时内存和性能预算。
