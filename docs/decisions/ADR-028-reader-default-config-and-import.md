# ADR-028 阅读默认配置与导入交互修复

状态：采用。日期：2026-11-12。

## 原因

用户明确要求复制旧摸鱼岛阅读服务 accessToken 到 config，不再要求每次手动输入。此前 ADR-025 的仅内存手动配置造成默认搜索未携带旧版所需参数。添加弹窗使用 Portal，而搜索输入样式依赖 workspace 祖先，导致展开后呈现浏览器默认输入框；固定空结果区还造成过量留白。

## 决策与影响

按本次用户明确授权，在 app/config/reader-service.ts 提供旧版阅读服务默认配置，app 注入 reader 控制器，统一用于搜索、目录和正文请求。该例外仅限用户指定的旧版浏览器阅读服务常量，不涉及账号登录会话、密码或其他服务凭证。前端配置随浏览器资源分发，不能被视为秘密存储；配置值不输出到日志和验收记录，不写入用户书架持久化。可使用 VITE_READER_ACCESS_TOKEN 覆盖公开客户端配置；测试构建必须覆盖为合成值，避免记录真实配置。运行时覆盖只保留在当前会话，清空后恢复项目默认值。

独立 BookImportDialog 拥有本地文件导入与反馈，OnlineSearch 拥有检索状态、重试/继续分页和结果展示；样式直接绑定控件自身类名，不依赖 Portal 外祖先。待机、空结果、错误采用紧凑状态区；有结果才提供独立列表滚动。顶部关闭、结果操作与底部导入在手机可触达，不改动共享 Dialog 的默认行为。

进入阅读路由时同时准备全局阅读宿主包装模块，避免点击已缓存书籍后才额外加载包装块而出现无反馈的等待；其他页面仍不加载阅读模块。

## 替代方案

继续要求每次粘贴凭证不满足用户要求；复制整套旧 Ant Design 组件违反依赖边界。仅加一个全局 input 规则会污染其他业务，故以组件局部样式修复。保留现有分层和依赖，不新增 UI 库。

## 验证

核对三个 reader3 端点的 accessToken 参数；合成凭证单元/浏览器测试覆盖默认值、会话覆盖、清空恢复及不落盘。验证真实服务时只报告鉴权结果和成功/失败数量，不打印配置或完整请求 URL。全部注册主题 × 明暗 × 桌面/375px/390px 覆盖导入弹窗初始、loading、empty、error、success、分页、添加、键盘关闭/焦点返回及手机触屏流程；执行 npm run check。
