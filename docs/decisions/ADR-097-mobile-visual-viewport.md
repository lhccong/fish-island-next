# ADR-097：手机输入区跟随可视视口

状态：已采用。日期：2026-11-17。

原因：手机软键盘通常只缩小 VisualViewport，100dvh 工作台仍占布局视口，@ 后聚焦会使输入区和发送按钮被键盘遮挡。

决策：app 的独立 MobileViewport 组件监听 VisualViewport resize/scroll 和窗口 resize，以 CSS 变量提供可视高度及顶部偏移；既有工作台外壳与手机全屏 FloatingWindow 使用同一呈现契约。仅在 760px 以下且无捏合缩放时更新，不进入 React 业务状态；卸载移除监听和变量。不修改输入焦点、滚动容器、草稿、请求或连接。

替代方案：仅用 dvh 无法覆盖只缩小可视视口的浏览器；固定键盘高度不适应不同输入法；逐次 scrollIntoView 无法保证发送按钮可达且会争抢聊天滚动。

影响：所有主题的手机工作台和浮窗共享可视区域；桌面保持现有尺寸，浏览器无 VisualViewport 时使用 dvh 回退。保留原生输入法与安全区。

验证：全部注册主题 × 明暗 × 375px/390px/桌面；自动化模拟只缩小 VisualViewport 及顶部平移，验证 @、引用、多行、发送/失败重试、收起键盘和小窗，检查无横向溢出及不新增请求/连接。自动化不能代替 iOS/Android 真机键盘，未验证范围须报告。
