# ADR-095 在线成员实时同步

日期：2026-11-17。状态：已采用。

## 原因与协议

原成员列表只在聊天页挂载和手动刷新时读取 HTTP 快照，长时间停留会显示过期人数。后端已有 `userOnline`（成员数组）和 `userOffline`（用户 ID）通知；每条连接登录后第一条 `userOnline` 为全量快照，之后为上线增量。该约定来自 WebSocketServiceImpl 的 login/online/offline 实现，同一账号多连接仅在最后一条连接关闭时广播下线。

## 决策与影响

- domain 保留消息事件边界，新增成员事件及传输事件联合；infrastructure 复用 HTTP 成员校验，丢弃畸形通知，每条新连接重新识别首个合法全量名单。
- 复用账号唯一连接；chat 实时控制器将成员事件立即分发到独立成员控制器，不提交消息 store，不影响消息列表和草稿订阅。
- 成员控制器持有账号内存快照，聊天页首次需要时读取 HTTP 作为兜底。现有 Provider 改为订阅该控制器，经典右栏、聊天列表、详情和 @ 候选共享状态；页面卸载不丢失连接期间收到的名单。
- 全量 WebSocket 快照替换旧名单并取消旧 HTTP 请求。HTTP 请求期间按 ID 记录增量，响应后重放，防止迟到响应复活已下线成员或丢失新成员；重复上线按 ID 更新、重复下线无副作用。请求失败保留既有错误/重试流程，后续全量快照可恢复。登出/账号切换取消请求并清理成员。
- 不增加轮询、连接、依赖或业务样式。主题、模式、面板显隐不作为请求/连接依赖；明暗模式、全部外壳沿用同一呈现和语义 token。

## 替代方案

收到通知后重新请求 HTTP 实现简单，但频繁上下线会造成额外请求和竞态；固定轮询存在延迟。直接在右栏处理通知会遗漏其他成员入口并重复业务逻辑，因此均不采用。

## 验证方式

单元测试覆盖通知校验、首帧/重连全量识别、去重、增删、HTTP 竞态、取消和账号清理，并断言成员更新不通知消息 store。浏览器使用合成账号/名单和 WebSocket 帧，按注册主题 × 明暗模式 × 1280/375/390px 验证 loading/empty/error/success、上下线与重连、面板关闭后更新、草稿/滚动保留、无横向溢出；执行 `npm run check`，实际结果记录在交付审计中。不将合成测试宣称为生产服务联调。
