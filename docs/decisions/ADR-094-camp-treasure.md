# ADR-094：营地挖宝与服务端积分结算

状态：采用。日期：2026-11-16。

## 原因与规则

营地增加可点击的五处挖宝地点。账号每天（Asia/Shanghai 零点分界）最多开始五次挖宝；初始有一次机会，以服务端五秒挖掘结束时刻起计时，隔一小时刷新一次机会，不累积。五处地点任选一处，共用次数与冷却，不改变普通散步。挖掘持续五秒，随机奖励为等概率的 1–10 可用积分。

## 决策与影响

- 沿用 domain/pet → infrastructure/pet → features/pet，由 app 既有账号刷新端口更新积分。独立挖宝控制器拥有加载、操作、倒计时及取消；不把定时更新提升到整个伙伴工作台。
- 后端新增 `/pet/treasure/status`、`/start`、`/finish`。数据库持久化挖掘记录、服务端时间和随机奖励；开始占用每日次数，完成接口检查五秒期限，账号积分锁包裹数据库事务，奖励、流水及完成标记一起提交。重试完成幂等，刷新、跨标签页、换肤和客户端改时间不能重置额度或重复领积分。
- SQL `sql/20261116_pet_treasure.sql` 必须在部署后端前执行。新增表是实际记录与幂等依据，不使用本地存储伪造积分或只靠 Redis TTL 保存额度。既有用户配置不修改。
- 当前挖掘跨零点继续占用开始当天次数；每日额度重置不清除一小时冷却。超过五秒但未结算的挖掘恢复后继续结算，不自动丢弃或重复开始。
- 地点是具有名称的原生按钮；挖掘时禁用散步与新挖掘。使用铲子、土尘、光点与有语义的进度条，减少动态效果时停止装饰动画，保留时间和结果。加载反馈复用 LoadingIndicator，失败可重试且保留服务端挖掘身份。
- 全部外壳使用同一场景与业务状态。沿用 pixel/pet 与工作台语义 token，无新依赖、字体或皮肤权限。桌面信息横排，手机场景外纵向反馈与至少 44px 地点入口；主题模式切换不请求、不丢位置或挖掘进度。

## 替代方案

客户端随机奖励/本地次数可被刷新和改时间绕过，拒绝；引入粒子或游戏引擎超出五个地点的需求，采用 CSS 与现有 Lucide 图标。

## 验证

执行 npm run check、后端针对性单元测试；浏览器覆盖全部注册主题 × 明暗 × 1440/375/390，包括加载、无伙伴、失败、恢复、五秒进度、奖励、冷却、每日上限、换肤连续性、键盘及触屏。模拟接口验证不替代真实数据库、Redis 和后端部署联调，未验证项明确说明。临时构建、截图和报告读取结论后清理。

实际结果与未验证项见 [营地挖宝验收记录](../audits/camp-treasure.md)。

## 2026-11-17：实际 JSON 时间戳协议修正

后端既有 JsonConfig 将 long/Long 序列化为十进制字符串，包含 serverNow、resetAt、nextAvailableAt 及 active.readyAt。原适配器只接受 number，模拟接口也只返回 number，导致真实正常响应被判定为“挖宝状态异常”。在 infrastructure/pet 中将规范的非负十进制时间戳字符串严格转换为安全整数，同时保留 number 兼容；拒绝空串、空白、指数、负值、非整数及精度溢出，计数与奖励仍按 int 的 number 协议校验。领域及 UI 继续只接收 number，不改变后端全局序列化、额度、奖励或业务生命周期。

后端回归测试使用实际 JsonConfig 序列化 VO；前端单元测试覆盖初始、挖掘中及已结算状态的数字串时间戳，浏览器夹具默认采用真实序列化形态，重新验证原有主题与视口矩阵。

## 2026-11-17：复用统一积分服务

按用户要求，挖宝结算改为调用 UserPointsService.updateUsedPoints(userId, -reward, PET_TREASURE.getValue(), digId, "营地挖宝奖励")，积分和流水均由既有五参数重载处理，删除 PetTreasureMapper 中独立的余额更新和流水插入 SQL。负数减少 usedPoints，从而增加可用积分，累计积分和等级不变。

保留原有账号积分外层锁、TransactionTemplate 事务及完成标记条件更新。统一方法的账号锁可重入；只有本次成功写入完成标记时才发奖和安排既有播报，重复领取不再次调用积分方法。五参数重载补查 updateById 和 addPointsRecord 的 boolean 返回值，失败抛出 BusinessException，交由挖宝现有外层事务一并回滚完成标记、余额和流水。两参数重载、全局锁及事务所有权不变。

独立 SQL 虽可在同一事务中结算，但重复了统一积分入口的职责，按本次要求移除。不新增接口、数据表、依赖或前端呈现变更。验证覆盖统一方法的奖励符号、来源及流水、写入失败抛错，以及挖宝的幂等、回滚重试和播报顺序；执行前端 npm run check，不以模拟浏览器接口替代后端验证。
