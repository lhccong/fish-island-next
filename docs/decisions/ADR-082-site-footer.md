# ADR-082 全站备案页脚

状态：已采用。日期：2026-11-15。

## 原因与方案

用户最终要求：电脑端备案文字位于各页面实际内容滚动区的末尾，随内容滚动，禁止固定在窗口底部；手机端仅首页透明悬浮显示。所有页脚保持透明，不设置独立底色。

站点文案仅由 app/components/SiteFooter 持有。shared/ui/PageFooter 提供无业务状态的 Provider/Outlet 表现插槽，app 注入内容；外壳在主内容 ScrollArea 末尾放置 Outlet，拥有独立滚动区的业务组件在其正文末尾放置 Outlet。未放置 Outlet 的弹窗不显示备案；隐藏的业务面板随其内容一起隐藏页脚。

聊天将 Outlet 放在输入区底部的操作行，复用现有留白，不在工作台外分配独立高度。独立页面在正文末尾放置 Outlet。页脚不改变请求、草稿、分页或连接。

伙伴页补充：app 使用既有 contentScroll=false 接管同一个主内容 ScrollArea，继续启用 fillContent；Outlet 放在 PetWorkspace 的营地背景容器内，正文弹性填充剩余高度。避免营地 min-height:100% 与外部页脚叠加，造成短内容也需要额外滚动一段才能看到备案。保持单一主滚动容器，手机沿用全局页脚隐藏规则。

手机所有正文 Outlet 隐藏，AppRoutes 单独注入仅首页可见的透明悬浮呈现，避开底部导航与安全区域，备案链接保持 44px 触控高度；其他手机页面不显示。

## 影响与替代方案

没有新增依赖。共享插槽只传递 ReactNode，不包含站点文案、路由判断或业务状态；业务与外壳仍仅依赖 shared 的公开入口。

逐页复制文案容易不一致；固定在窗口底部会覆盖内容；独立外壳底栏会抬高聊天输入框；将正常流页脚放到固定高度工作台之外会产生外层滚动，均不采用。

## 验证

执行 npm run check；按全部注册主题 × 明暗 × 桌面/375px/390px 验证首页加载、失败、空数据及成功，检查桌面滚动到末尾才显示页脚、手机首页透明悬浮及其他页面隐藏。验证独立滚动页与聊天输入操作；未验证项明确报告。
