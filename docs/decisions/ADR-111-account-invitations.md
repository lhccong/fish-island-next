# ADR-111 账号邀请

状态：已采用。日期：2026-11-26。

用户可通过账号菜单查看邀请码、复制注册链接和使用二维码。支持 Web Share 的浏览器可调用系统分享。链接从当前站点生成，直接打开邮箱注册表单并预填邀请码，表单也支持手动输入。注册仍然开放，邀请码选填。每个账号有一个可复用的随机邀请码。成功注册时记录邀请人，邀请成就由 ADR-107 结算。

app 只装配账号菜单入口及注册路由，auth 负责邀请码状态、表单草稿和会话作用域，infrastructure/auth 校验 HTTP 响应。`POST /api/user/invitation` 取回或生成当前账号的码。后端通过 MyBatis Mapper 和唯一索引查询邀请码，通过条件更新保证并发请求使用同一个码。邀请人必须是有效账号。邮箱注册校验码后，在创建用户的同一次插入中写入邀请来源，既有匿名注册请求仍然有效。

## 6 位邀请码（2026-11-27）

为方便口述和手输，首次生成采用 6 位随机字母数字码，排除容易混淆的 0、O、1、I 和 L。新码与已发出的 16 位码共用用户表的 `invitationCode` 字段和唯一索引。每个账号复用已存的码，生成冲突时重新抽取。考虑过额外保存短码或替换旧码，最终采用单列以保留已分享链接和旧码的注册能力。

已有数据库沿用 `sql/20261126_user_invitation.sql`，新建库可使用 `sql/create_table.sql`。分步部署时先更新兼容两种格式的前端，再启用生成 6 位码的后端。

二维码使用 `qrcode.react`（ISC，内置的编码器为 MIT），无新增传递运行时依赖，随邀请弹窗异步加载。考虑过使用远程二维码服务和自写编码器。本机生成可以避免发送分享地址给第三方，同时复用已有的标准编码实现。

## 打开即读取

首次打开邀请弹窗时直接调用既有取回或生成接口。成功结果与在途请求归当前登录会话所有，关闭或再次打开时复用。刷新后从服务端取回同一码，登出、换账号或重新验证会话时清空缓存并取消在途请求。失败后可以重试。相比为每个弹窗保留本地状态，会话缓存可跨外壳和页面复用，同时只在打开邀请时发请求。

邀请链接单独一行，邀请码与二维码组成紧凑分享面板。手机把码与复制按钮上下摆放。验证使用合成账号和拦截请求覆盖全部主题、明暗模式及桌面、375px、390px 视口，检查打开即读取、重复打开、失败重试、复制、分享、焦点和滚动、链接预填及注册回执。后端验证短码复用、并发竞争重读、拒绝无效码以及通过新旧码注册均能保存来源。测试不向真实邮箱发送验证码。
