# ADR-042：聊天工具栏发送红包

状态：已采用。日期：2026-11-13。

## 原因与范围

用户要求补齐聊天工具栏的发红包样式与接口。沿用旧项目 `/api/redpacket/create` JSON 协议和类型 1 拼手气、2 普通、3 答题，创建后通过 ADR-038 的 HTTP 聊天发送发布 `[redpacket]ID[/redpacket]`。不复制旧 WebSocket 发送、不新增依赖、不改变服务端积分或权限规则。

## 决策

- domain/chat 增加创建参数、表单纯校验及可区分的创建错误。按照当前后端限制校验整数总额 1～100、份数不大于总额、整数除法每份 1～10；题目最多 200 字、答案最多 50 字。资格、余额和每日次数由后端决定，不伪造可用余额。
- infrastructure/chat 扩展既有红包端口，以 Sa-Token 和取消信号 POST JSON 创建，严格校验返回 ID。业务拒绝可修改重试；网络、5xx、无效响应等无法确定创建结果时明确提示并锁定重复创建，无自动写重试。
- features/chat 新建账号隔离的创建控制器，表单、进行中请求和已创建 ID 不放入页面/消息草稿。创建与消息发布分两步；发送控制器暴露返回稳定本地消息 key 的 enqueue，原 send 布尔契约保留。发布失败仅用同一消息 key/clientMessageId 重试，不重复创建或扣积分；仅收到 HTTP/WS 确认后展示发送成功。关闭弹窗保留账号内表单/进度，账号切换清除并取消旧请求。
- Provider 注入现有端口与聊天用例，主题/模式不参与创建生命周期。工具栏使用统一 Button 的 44px 图标入口；弹窗复用 Dialog、reserved ScrollArea、Select、Button。封面使用 ADR-040 的红包语义色，其余文字、字段、操作跟随主题；手机单栏、44px 控件、16px 输入及安全区域，正文滚动而标题/反馈/操作固定。

## 替代方案与限制

创建后直接提示“发送成功”会隐瞒消息发布失败；创建失败就无条件重试可能重复扣积分，均不采用。现有后端没有创建幂等键或按本人查询创建记录的接口，未知创建结果不能自动恢复；如需跨刷新恢复，应先补后端协议。关闭弹窗不代表取消服务端已执行的创建。

## 验证

单测覆盖约束、请求协议、未知结果、创建互斥、发布失败只重发与账号切换取消。浏览器按全部注册主题 × 明暗 × 桌面/375px/390px 覆盖表单、选择器键盘/触屏、滚动与焦点、校验/拒绝/创建中/发布失败/成功、草稿与模式保留及无横向溢出。执行 `npm run check`，保留验收报告并清理本轮测试产物。

## 发送表单视觉与默认值调整（2026-11-13）

用户指定默认总积分100、红包个数10，首次打开及成功后“再发一个”均采用这组默认值；关闭重开继续保留当前账号草稿。参考用户提供的简洁红包表单，取消橙色预览横幅、并排的小输入及固定高度大留白，采用画布底色上的独立横向字段行，金额/个数右对齐、祝福语独立卡片、底部总积分汇总。积分不使用人民币符号；保留拼手气/普通/答题三类、服务端校验与创建/发布两阶段状态。不引入未接入的红包封面或表情入口。

普通发送/关闭按钮继续使用共享主题动作色和32px桌面/44px手机尺寸，金额汇总承担视觉重点。固定标题和底部反馈/操作，正文使用reserved ScrollArea，桌面24px/手机20pxgutter。所有主题及明暗复用语义色；小屏和键盘缩短视口时正文滚动且关闭、错误与提交入口可达。验证默认值、总额联动、类型切换、校验、拒绝/创建中/发布失败重试/成功重置、关闭草稿和换肤保留。
