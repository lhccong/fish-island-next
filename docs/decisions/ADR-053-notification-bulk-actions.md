# ADR-053 通知角标与全量操作

状态：采用。日期：2026-11-14。

原因：原前端只统计已加载通知；后端 batch/set/read 忽略 IDs，点击单条通知会误将全部已读，批量删除不能覆盖未加载记录。

方案：domain/fish-circle 增加未读计数和全量操作端口；infrastructure 适配 GET event_remind/my/unread/count、POST all/delete、batch/read（指定 IDs），保留 batch/set/read 的全部已读兼容语义。后端所有条件限定登录接收者；全量变更为空时也幂等成功，不修改旧版批量删除协议。

feature 账号作用域 Provider 统一持有未读数，经 app 注入服务与账号；导航、发现入口及铃铛共用角标。轻量 notifications 子模块通过自身 index.ts 公开，避免导航导入鱼小圈工作区及其样式破坏懒加载。登录、回到前台、打开/刷新列表、变更成功时回读；前台每 60 秒更新，非实时推送。请求串行、支持取消，退出/换账号丢弃旧响应。主题和模式不参与生命周期。

全部已读覆盖未加载通知；全部删除经通知面板内明确确认。两种全量操作成功后刷新列表和计数，取消尚在途的分页响应，避免旧页再次带入未读状态；失败保留列表并允许重试。单条已读仅处理目标 ID。保留管理选中删除能力。使用共享 Button、DropdownMenu、reserved ScrollArea 和语义 token，桌面紧凑、手机重排确认区。

替代方案：遍历所有分页再批量操作会有漏项、额外请求及并发变化问题；通过已加载数组推算总未读不准确，均不采用。无新增依赖或皮肤权限。

公开入口约定补充：ESLint 仅允许 app 使用 `@/features/fish-circle/notifications` 这一明确的子模块 index.ts；其内部文件仍禁止跨层访问。fish-circle 内部使用 `./notifications`。这一窄范围例外用于保持工作区懒加载，不能推广为任意深层导入或跨 feature 依赖。

验证：前端协议单测；后端账号条件、空集幂等和单条/全部范围单测；全部注册主题 × 明暗 × 桌面/375/390 浏览器验证角标、滚动、全部操作及失败恢复，检查换肤无额外请求。部署需要前后端一起更新。
