# ADR-076 管理工作台迁移

状态：采用。日期：2026-11-15。

## 原因与范围

迁移旧版数据分析、用户、称号、标签、词库、装备、举报七项真实管理能力。旧版依赖 Ant Design、ProTable 和 Umi，不能直接复制组件。

## 决策与影响

- 新增 domain/admin 定义管理实体和端口，infrastructure/admin 适配现有接口，features/admin 拆分列表、编辑、称号分配、举报处理和统计；app 注入账号凭证并组合懒加载路由。
- app 同时约束菜单和 `/admin/*` 路由，仅已认证且 role 严格为 admin 的账号可进入。检查会话期间不挂载管理功能；服务端原有管理员权限校验继续生效，客户端隐藏不替代服务端鉴权。
- 桌面将管理入口放在最左侧主导航的发现图标下方，WPS 对应顶部功能区入口；点击后直接进入管理工作台，左侧复用朋友圈的列表导航，右侧显示模块，不使用下拉菜单。手机从发现进入独立管理目录 `/admin`，进入子页后通过“返回管理页”切换模块。沿用工作台外壳、语义 token、共享控件、reserved ScrollArea 和滚动分页，不新增依赖。
- 写操作显式确认并保留失败表单；凭证、账号切换和卸载取消请求。外观变化不参与请求依赖，不清空草稿。传输层只挑选业务字段，禁止将用户接口返回的密码等无关信息传入组件。

## 替代方案

跳转旧站不能完成新站迁移；复制旧版 UI 引入第二套框架，且无法满足主题、暗夜、手机及滚动分页规范，因此不采用。
