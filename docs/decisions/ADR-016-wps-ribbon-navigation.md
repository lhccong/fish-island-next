# ADR-016：WPS 顶部功能区导航

状态：已采用。日期：2026-11-11。

## 原因与决策

用户要求 WPS 模式的菜单移到顶部，并穿插于类似 WPS 的工具区。新增 wps 外壳标识，由 app 的 WorkspaceLayout 显式按当前内置主题选择；皮肤配置仍只提供颜色。现有 WechatShell 作为共享稳定的网格布局实现，接收 rail/ribbon 导航布局参数，避免切换组件类型造成业务内容、草稿和主题弹窗重挂载。

顶部文档标签行直接承载聊天、热榜和鱼小圈三个路由菜单，每个菜单为独立标签，使用 aria-current 标识当前页；不新增一套页面状态或在工具栏重复入口。账号和主题入口保留在下方工具区。未实现的办公工具使用非交互示意，不伪装成可用编辑能力。手机标签自适应分配宽度，触控目标至少 44px，不复制整条桌面工具区。桌面文档标签按截图采用 30px 密集高度，作为组件规范允许的桌面密集导航场景单独验证。

按用户进一步提供的 WPS 截图，桌面细化为 36px 文档标签栏、36px 菜单快捷栏和 76px 工具区；工具区统一连续白底，复现剪贴板、字体、对齐、数字、单元格及操作组的密度与分隔线。工具示意通过辅助名称和悬停说明标识，不在底部添加破坏参考外观的提示行。1920px 为原图对齐视口，较窄桌面隐藏次要示意组，核心导航保持可用。

## 影响、替代方案与例外

热榜、聊天占位页及鱼小圈共用组合组件，无新依赖，无通信或业务状态变化。第三方皮肤不控制布局。选择其他主题恢复既有侧边导航。未采用按主题复制整个外壳模块的方案：仅网格区域变化，复用同一组件可保留输入和弹窗状态。这是外壳实现共享的明确决策，不复制业务逻辑。

## 验证

执行 npm run check；桌面、375px、390px 验证顶部位置、功能导航、主题切换和关闭焦点、草稿和请求次数保持、刷新恢复、页面无横向溢出；覆盖热榜加载、空数据和失败状态。保存桌面和手机截图。
