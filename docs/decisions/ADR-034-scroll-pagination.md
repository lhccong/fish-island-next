# ADR-034：统一滚动分页

状态：采用。日期：2026-11-12。

## 原因

用户要求所有列表使用滚动分页。现有动态、评论、互动通知、伙伴物品/外观/领取记录和阅读搜索仍需点击翻页或加载更多，打断连续浏览。

## 决策与影响

共享 `InfiniteScroll` 负责观察最近滚动容器内的列表末端，提供语义状态和失败重试；共享 `useInfinitePages` 处理普通页码列表的串行请求、取消、稳定 ID 去重和追加状态。领域 DTO 仍由 infrastructure 映射，feature 仅适配 items/records。阅读搜索保留已有流式协议及游标，由同一观察器触发续载。打赏列表复用观察器与分页 Hook，原领域控制器仅保留协议适配。

普通列表下滑追加，评论的“查看更多”仅展开已加载预览，不承担分页。通知批量已读的范围改为已加载消息。后端页码保持不变；空页、全重复页或累计达到总数即结束。追加失败保留内容与当前页，通过重试恢复，禁止自动重试循环。主题和明暗切换不参与请求依赖。

无新增依赖，不改变外壳、主题体系或权限。后续聊天历史按性能规范向上加载、保持锚点，并使用有界缓存，本变更不接入未实现的消息协议。

## 替代方案

保留翻页按钮不符合连续浏览要求；一次获取全部数据会增加流量与等待；各业务单独复制观察器易造成容器、并发及清理行为不一致。

## 验证

执行 npm run check；浏览器以合成数据验证所有主题 × 明暗模式 × 桌面/375px/390px 的追加、结束、空数据、首批/追加失败及重试、去重、筛选刷新和键盘/触屏滚动。验证范围与限制记录在 docs/audits/scroll-pagination.md。
