# ADR-071 积分商城迁移

状态：已采用。日期：2026-11-15。

## 原因与边界

迁移旧 `/avatarFrames` 的头像框、道具、积分记录及相关介绍，提供发现区「积分商城」入口 `/utils/avatar-frames`，旧地址重定向到该入口。旧 Ant Design 页面不复制，保持现有 React/Radix 与语义 token。

## 决策与影响

- domain/points-shop 定义道具、流水及端口，infrastructure/points-shop 解码旧 props 和积分流水协议，features/points-shop 独立管理分页及兑换确认；app 注入账号、刷新与头像框插槽。
- auth 的头像框组件增加嵌入呈现并经 index.ts 导出，由 app 组合进商城；两处共享兑换/穿戴逻辑，商城不跨 feature 导入。账号新增静默资料刷新，避免兑换后进入 checking 重挂载页面及重连。
- 道具只允许后端已实现的月卡类型兑换，未知类型明确不可兑换。价格、余额和流水来自真实服务；服务端确认成功后单独刷新账号，读取失败不诱导再次兑换。
- 月卡增加一个月会员时间，永久会员支持入口指向现有支持页面；不复用旧页面把月卡和永久会员混为一谈的说明。
- 头像框、道具及积分记录使用既有滚动分页，追加失败保留内容；账号变化取消请求，主题/模式不参与请求依赖。共享 ScrollArea 保留 gutter、手机隐藏滑轨。

## 替代方案

复制旧商店会引入第二套 UI、日期依赖及不受控状态；商城重复实现头像框会导致资料更新和穿戴规则分叉，均不采用。

## 验证

执行 npm run check；端口测试覆盖旧字段映射、无效响应、鉴权及兑换确认；浏览器覆盖全部注册主题 × 明暗 × 桌面/375/390，加载、空、错误、成功、分页、兑换失败恢复、键盘关闭、主题切换保留状态。仅使用合成账号与拦截接口，不对真实账号消费积分。

## 字符串分页总数兼容修复

后端 JsonConfig 将 Long（含 MyBatis 分页 total）序列化为十进制字符串；头像框、道具与积分记录在基础设施解码时兼容安全非负整数及其规范十进制字符串，UI 继续接收 number。价格与积分字段仍按 Integer 协议严格校验，ID 保持字符串，超精度和非法总数仍拒绝。回归夹具改用服务端真实字符串总数，避免只用数值总数掩盖协议差异。
