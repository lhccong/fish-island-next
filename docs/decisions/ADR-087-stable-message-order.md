# ADR-087 聊天消息顺序不依赖客户端时钟

日期：2026-11-16。采用。

## 原因

旧客户端提交自身设备时间，实时消息的 timestamp 不是服务端递增序号。每批按 timestamp 重排会让已显示的消息被后来到达、但时间较早的消息挤向下方；发送确认更新本地时间后也会在下一批重排。

## 决策与影响

实时消息按接收顺序追加，确认保留本地消息位置和 key。时间戳仅用于显示，不参与排序或窗口淘汰判断。历史页按服务端 createTime/id 降序协议反转，再围绕已有消息锚点插入缺失记录，不重排已显示记录。没有重叠锚点时，旧页放在头部，最新页放在请求开始前的末条消息之后、请求期间新到的实时消息之前。保留去重、撤回墓碑、1000 条窗口与发送中/失败消息固定策略，以有界已淘汰 ID 集合阻止近期重放。

不新增接口、连接、依赖、主题或表现分支。相比用本机接收时间覆盖原时间，此方案保留原始时间；相比直接按消息 ID 排序，兼容 UUID、客户端时间 ID 和服务端 ID。没有服务端全局序号时无法保证跨客户端完全一致的顺序，也不保证超过去重缓存范围的旧重放。

## 验证方式

单测覆盖逆序时钟、同时间 UUID、后续批次、确认改时、历史/实时重叠、刷新无重叠、淘汰重放。浏览器覆盖全部注册主题、明暗模式、桌面与 375px/390px 的真实入站追加与历史状态；执行 npm run check。实际执行结果及未验证项在交付中说明。

本次浏览器以合成 HTTP/WS 数据执行 84 项并全部通过：摸鱼岛、像素风、WPS、微信、企业微信、飞书、钉钉 × 明暗 × 桌面 1280px/375px/390px。覆盖空态、加载、失败重试、历史成功及结束、上翻锚点、去重撤回、草稿保留、实时逆时钟追加和无横向溢出；桌面验证换肤/模式不新增请求或连接，手机验证触屏重试与返回最新消息。抽查桌面与两种手机截图后清理临时产物。真实后端、实体设备软键盘、长时性能及跨客户端全局顺序未验证。
