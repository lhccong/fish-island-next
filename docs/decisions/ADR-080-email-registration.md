# ADR-080 邮箱注册迁移

状态：已采用。日期：2026-11-15。

原因：登录弹窗缺少旧摸鱼岛的注册入口。旧版主要调用 `/api/user/email/send` 与 `/api/user/email/register`，账号选填，邮箱、验证码、密码与确认密码必填，成功后返回登录。

决策：在现有 auth 分层扩展公开注册端口，HTTP 适配保留旧字段，注册表单独立拥有请求、草稿、倒计时与取消生命周期，不改变会话状态。成功仅在服务端返回有效用户 ID 时确认，随后清空注册密码并以邮箱预填登录；不自动登录。邮箱使用完整地址输入，避免后缀列表限制可用邮箱。

旧 UI 的 captchaVerification 未被邮箱注册控制器读取或校验，因此不迁移该界面的滑块，也不修改服务端验证规则；账号密码注册 `/register` 的滑块协议不在此次范围。替代方案是完整复制旧表单及滑块组件，会引入第二套 UI 与无效验证步骤，故不采用。

影响：全部主题、明暗模式和外壳共用一个登录/注册弹窗；正文使用 reserved ScrollArea，标题和关闭入口固定。注册与验证码请求不携带会话令牌，不持久化密码；关闭时取消请求。验证码发送成功后倒计时 60 秒，服务端仍为最终频率与邮箱规则的权威来源。

验证：适配器测试检查匿名字段、成功响应及拒绝；浏览器覆盖全部注册主题 × 明暗 × 桌面/375/390，验证发送、重复提交、密码不一致、失败重试、成功返回登录、滚动与关闭。只用合成数据和拦截接口，不向真实邮箱发送或创建真实账号。

## 注册昵称

邮箱注册打开时预填「岛民」加四位随机数字。用户可在表单内随机换一个、手动修改或清空，沿用个人资料的 10 字符限制。端口使用 `name`，HTTP 请求使用 `userName`。服务端去掉首尾空白，在创建用户时写入收到的昵称；字段缺省或只含空白时写入同格式的默认昵称。昵称为显示字段，可重名。老客户端省略该字段时也能获得默认昵称，验证码与登录流程沿用原协议。

在插入用户时写入昵称，可与账号一起保存。也考虑过注册后再补写昵称，该方案需要额外的写入，并可能在首次读取时返回空昵称。注册表单沿用现有主题样式和独立滚动区。通过服务端测试检查自填、默认与超长校验，通过适配器和浏览器测试检查预填、重新生成、请求字段、提交失败后保留昵称及留空注册。
