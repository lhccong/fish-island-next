# ADR-084 聊天页小窗模式

状态：采用。日期：2026-11-16。

## 原因与范围

聊天输入工具栏增加小窗图标，参考旧摸鱼岛的页内悬浮聊天。小窗为站内跨菜单悬浮模式，不是操作系统置顶窗口；可在热榜、发现等其他菜单继续使用，文档画中画暂不引入。

## 决策与影响

feature/chat 的独立 ChatWindowProvider 按账号管理普通、小窗、收起状态。app 的 ChatPageHost 在小窗开启时保持聊天页挂载，普通外壳在其他菜单隐藏，小窗 Portal 保持可见；未开启时离开聊天页正常卸载。开启小窗后 app 导航到热榜，关闭和返回完整聊天均导航回聊天。登录弹窗期间隐藏小窗，账号变化释放旧状态。ChatWindow 管理 DOM 迁移。使用稳定 DOM 宿主和 React Portal，在普通插槽及 shared/ui/FloatingWindow 之间移动同一内容，不复制消息列表、编辑器、业务用例、历史请求或账号连接。关闭、返回完整聊天均恢复原插槽，Esc 收起，小窗内草稿保持；卸载清理宿主。

FloatingWindow 增加 compact 变体和可选操作名称，原游戏窗口默认行为不变。桌面初始 360×520，可拖动和调整大小；手机沿用 760px 断点全屏、安全区及 44px 控件。聊天输入按容器宽度重排工具，WPS 的小窗使用普通会话呈现，退出恢复工作表。配色复用全部主题的语义 token。WPS 完整聊天在窄容器内将工具移至第二行，页头操作横排，保留输入宽度。外壳增加可选 mainContentId，由 app 在隐藏的聊天外壳上移除正文锚点，避免其他菜单出现重复 ID；默认外壳行为不变。

## 替代方案

- 复制旧 FloatingChat：产生第二套消息、发送和连接逻辑，拒绝。
- 重新挂载组件或改变 Portal 目标：会丢失局部状态及滚动位置，拒绝。
- 系统弹窗/文档画中画：跨窗口样式、焦点与浏览器支持范围扩大，当前不采用。

## 验证

执行 npm run check；全部注册主题 × 明暗 × 桌面/375px/390px 检查入口、草稿和 DOM 身份、接收和发送失败重试、收起恢复、关闭及焦点、无横向溢出。验证小窗拖动缩放、手机触屏工具展开、加载/空/失败反馈及请求/连接计数。测试产物提取结论后清理。

### 验收记录（2026-11-16）

Windows / Playwright Chromium 开发服务器，合成账号、消息及 HTTP/WS 夹具；无真实账号和聊天记录。小窗专项覆盖 pixel-island、wps、wechat、wecom、feishu、dingtalk × light/dark × 桌面、375px、390px，包括加载、空、历史失败恢复、消息接收、发送失败重试、跨菜单、拖动/缩放/最大化、收起恢复、草稿与 DOM 保留、主题切换和请求/连接计数。两组专项各 36 项通过，并检查桌面与手机截图；小窗独占聊天 DOM。

额外回归普通输入、WPS 工作表及游戏窗口。修正存量测试的像素侧栏名称、路由卸载等待及加载反馈定位；未调整真实业务以满足测试。手机项目跳过仅适用于桌面的 WPS 公式栏断点用例，手机布局由其他矩阵用例覆盖。未进行真机软键盘、真实后端、跨浏览器兼容及性能预算实测；不据此宣称性能达标。临时截图和 trace 提取结论后清理。

最终普通聊天、小窗、WPS 和像素主题游戏窗口回归共 132 项：128 直接通过、2 项游戏键盘 Home 回顶断言首次超时后重试通过、2 项手机项目的桌面专用公式栏用例跳过。两项不稳定回归均位于 game-windows.spec.ts 的股市滚动流程，未修改游戏滚动业务。小窗加载/外观专项另有 36 项通过。
