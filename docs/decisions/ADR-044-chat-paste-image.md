# ADR-044 聊天粘贴图片自动上传

状态：采用。日期：2026-11-13。

## 原因与协议

对照旧版 Chat 的 handlePaste、handleImageUpload 和 handleSend：输入框粘贴图片后使用 `/api/file/minio/upload?biz=user_file`，multipart 字段为 file；上传成功仅进入待发送预览，点击发送才将 `[img]URL[/img]` 与文字一起交给现有发送用例。

## 分层与交互

domain/chat 增加图片上传端口，infrastructure/chat 适配鉴权、取消、超时与安全 URL 校验，app 注入。独立账号级图片控制器持有上传、失败、待发送状态，不放入页面或消息 store；外观切换与路由返回保留待发送图片，登出/换号取消旧请求。移除取消上传，迟到响应不能恢复已移除图片；失败可显式重试。

同一草稿保留一张图片，已有图片时提示先发送或移除，避免覆盖。纯文本粘贴使用浏览器行为，多张图片粘贴明确提示一次一张。支持 PNG/JPEG/WebP/GIF，输入上限 10MiB；超过 1MiB 的静态图片用异步 canvas Blob 压缩为最长边 2000px 的 WebP（保留透明），目标 1MiB，无法达到时提示失败；GIF 保留动画原文件。该限制是客户端资源预算，非后端 user_file 限制。上传期间可编辑文字，但不能发送尚未完成的附件。

预览成功时仅显示 72px 图片，移除入口为右上角 X 图标，保留 44px 触控范围、可访问名称与键盘焦点；不显示全宽边框或成功文案。上传/失败反馈与重试仅在对应状态显示。反馈/重试复用语义变量和 Button，全主题与明暗模式共用组件；窄屏保留安全区。图片发送失败沿用消息发送重试，不重复上传。

## 替代方案与影响

不直接复制旧巨型页面及同步 DataURL 压缩循环；不粘贴后立即发送，保留用户检查内容和引用的机会；不增加全局粘贴监听，避免截获其他输入框。无新增依赖或主题权限。

## 验证

控制器测试取消、迟到响应、重试和账号释放；适配器测试 multipart、鉴权与 URL 校验。浏览器覆盖全部注册主题 × 明暗 × 桌面/375px/390px 的空草稿、上传中、失败重试、预览、移除、图片与文字发送、纯文本粘贴和无横向溢出。执行 npm run check，实际范围记录于 docs/audits/chat-paste-image.md。
