# ADR-003：热榜消息详情与统一滚动区域

- 日期：2026-11-11
- 状态：采用

## 决策

用户要求单个热榜以聊天消息样式展示，并统一改善滚动条。全部热榜保留卡片总览；侧栏选择来源、手机选择来源以及点击卡片标题进入同一只读消息视图。每个热点呈现平台头像、名称、原始排名、正文和热度，外链继续打开原文。时间仅显示来源实际更新时间，不制造逐条消息时间或发送输入框。

总览卡片只预览前 8 条，“查看全部”进入消息详情，不再展开卡片内的列表。ScrollArea 内部 table 包装层使用 fixed table layout 和明确宽度，防止不换行的来源摘要撑宽侧栏。

消息详情属于 features/hot-board 的表现组件，不复用真实聊天 store，也不接入 WebSocket。搜索、刷新失败保留旧数据和来源切换共用既有状态。返回全部时清除筛选；切换总览/来源重建滚动视口回到顶部，同一来源搜索或刷新不主动跳底。

新增 @radix-ui/react-scroll-area（MIT）并封装为 shared/ui/ScrollArea，沿用现有 Radix 体系，统一主内容和侧栏来源的滚动条。它提供保持原生滚动的细圆角浮层滑块、悬停显示和触屏滚动，不再依赖带箭头的系统滚动条。分类横向滚动使用轻量 CSS 隐藏装饰性滚动条，保留触摸与键盘操作。该依赖进入工作台入口，需随构建检查体积。

## 替代方案与验证

纯 CSS 可部分改善系统滚动条，但跨浏览器表现与显隐差异较大；选择统一 Radix 封装，不引入第二套 UI 框架。消息数量受现有每来源榜单大小限制，当前不额外引入聊天虚拟化逻辑。

验证卡片和侧栏入口、完整消息列表、原文链接、搜索与刷新、返回总览、切换来源回顶、键盘/触屏滚动，以及桌面、375px 和 390px 手机视口。真实聊天功能仍未接入。
