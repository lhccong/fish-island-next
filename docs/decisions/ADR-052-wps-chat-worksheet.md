# ADR-052：WPS 聊天工作表呈现

状态：已采用。日期：2026-11-14。

## 原因与决策

用户要求 WPS 模式的聊天界面采用 Excel 样式。app 显式向聊天功能注入 conversation/worksheet 呈现变体；WPS 使用行号、A/B/C 列标题、发送者/时间/消息内容单元格和当前群聊工作表标签，并隐藏左侧会话栏及消息称号。桌面隐藏群聊标题行，将输入放在表格上方的 ƒx 公式栏；编辑区高 32px，整行保持 44px 图标命中区，发送与详情入口各占独立列、间隔至少 8px。手机保留返回、列表和详情所在页头，公式栏保持触控尺寸。这里是聊天数据的工作表呈现，不提供电子表格编辑、公式计算或虚构的工作表操作。

同一 MessageStream、MessageRow 和 ChatComposer 始终保留挂载，输入与消息使用稳定 key 排序，使 DOM 焦点顺序与视觉顺序一致。消息按 ID 订阅、虚拟列表、历史向上滚动分页、消息菜单、图片、红包、失败重试与独立草稿继续复用。行号表示当前消息窗口中的位置，不作为消息 ID 或服务端序号。外观选择不进入请求、连接或历史加载 effect 的依赖。WorkspaceLayout 与 WechatShell 增加纯布局参数 hideDesktopHeader，不持有聊天状态。

窄内容区将发送者与时间重排到消息上方，保留行号和正文；手机保持紧凑输入、44px 操作入口、工具展开、软键盘和安全区。桌面消息内容末端预留 24px，手机预留 20px，焦点环在单元格内保留空间。所有颜色复用 surface/canvas/sidebar/border/text/muted/accent 语义变量，支持全部主题和独立明暗模式。

## 影响、替代方案

只增加受限呈现参数和 CSS 布局，不改变领域、通信、状态所有权、依赖或皮肤导入权限。未采用第二套消息表格、复制消息业务或电子表格依赖，以免状态分叉、切换重连及历史锚点丢失。其他主题继续采用会话气泡。

## 验证方式

执行 npm run check。浏览器按注册表全部主题 × light/dark × 桌面/375px/390px，验证加载、空数据、失败重试、正常消息、长文本、图片、发送失败、菜单引用/复制、成员面板、手机工具、滚动和无横向溢出。单独覆盖 WPS 历史连续分页、主题/模式往返后消息与草稿保留且无额外请求/重连。截图仅作临时验收，结论写入审计文档后清理。
