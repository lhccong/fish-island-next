# ADR-024：统一控件及展开面板外观

状态：已采用。日期：2026-11-12。

## 原因与决定

个人资料称号选择器收起时已有样式，展开后仍出现浏览器默认矩形列表和系统蓝色选中条，无法统一主题、明暗模式及交互反馈。将可检查的禁用模式写入 AGENTS.md 与组件规范：禁止原生 select 系统选项列表、仅美化触发器的实现，以及用于业务反馈的 window.alert/confirm/prompt。

选值组件使用 Select/Combobox 语义，操作入口使用 DropdownMenu；由 shared/ui 基于既有 Radix 技术栈封装，业务通过值和回调接入。首轮仅更新规范并登记问题；用户随后要求整改，实施决定见下文补充。

## 影响与替代方案

仅调整 select 或 option 的 CSS 无法可靠控制各平台展开列表，因此不采用。直接禁用全部原生 HTML 控件会损失语义和系统能力，因此仅约束未统一设计的产品外观，保留文件选择、密码管理、输入法和软键盘；已有主题样式的单选、复选和输入框不因使用原生标签被一律判错。

首次排查发现 2 个源码文件中的 3 处 select，另有评论图片的 1 处原生文件上传入口，共涉及 3 个源码文件，记录于 [排查清单](../audits/native-control-style.md)。整改及验证状态随实施更新；不能把登记视为通过视觉验收或获得规则例外。

## 实施补充：替换四处存量控件

用户确认整改后，新增 shared/ui/Select，按需引入 MIT 许可的 `@radix-ui/react-select`，复用既有 Radix 技术栈。通过 Portal 与 Popper 定位避开资料弹窗及滚动区裁剪，统一触发器、列表、选中标记、键盘与焦点恢复。替换称号、WPS 来源与分类选择器；隐藏评论 file 输入，使用可键盘触发的统一上传按钮并保留系统文件选择窗口。替代手写定位和键盘逻辑，避免在业务组件重复维护浮层行为。无新的 UI 框架，继续采用 npm 单锁文件；构建检查实际分包体积。

保留称号读取及保存失败、不可用当前项、来源分类筛选、评论上传及发送状态。新增浏览器验证并调整原生 selectOption 测试：全部主题 × 明亮/暗夜 × 桌面、375px、390px；WPS 筛选覆盖其对应外壳，选项展开、选中、键盘、关闭、滚动和触屏均纳入验收。

WPS 表格的来源切换属于筛选而非内容身份切换，使用稳定 contentKey，避免更换来源时重挂载表格、清空搜索/分类/排序及丢失选择器焦点；卡片与来源详情继续沿用既有身份规则。

称号异步保存会暂时禁用触发器，Select 在 Radix 关闭焦点回调中记录待恢复状态，并在解除禁用后恢复焦点，避免焦点落到弹窗外或丢失。生产构建当前 auth 共享块约 45 KiB gzip；未进行完整运行时性能基准。保留既有人生重开大资源块的构建提示，不把控件构建数据当作聊天性能实测。

新增 ESLint 门禁，禁止应用 JSX 中直接使用 select/datalist，Radix 内部不可见的表单桥接不属于可见的原生面板。执行 npm run check，并以浏览器覆盖全部注册主题 × 明亮/暗夜 × 桌面、375px、390px，以及展开、选择、关闭、键盘、触屏、焦点和异步状态，不能仅验收收起的输入框。
