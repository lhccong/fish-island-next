# ADR-102 聊天室大肥鱼

日期：2026-11-19。状态：已采用。

## 决策

大肥鱼是公共聊天室里的角色。后端在 HTTP 或旧 WebSocket 消息保存成功后匹配正文子串 `肥鱼`，覆盖 `大肥鱼` 和带 `@` 的写法。符合条件的普通文字消息以 30% 的概率进入插话候选。Redis 对触发消息去重，并对用户开启对话和群内插话分别限频。群内插话候选通过限频后调用模型，每 5 分钟最多一次，模型可选择保持沉默。模型调用使用独立的有界任务队列，对话在队列满时收到失败反馈。pre 环境通过 `application-pre.yml` 的 `fish.big-fish.api-key` 配置 DeepSeek，默认读取服务端 `DEEPSEEK_API_KEY`，未设置时留空。模型默认 `deepseek-flash`，可通过 `fish.big-fish.model` 调整。

同一用户首次命中关键词时开启 10 秒滚动续聊窗口，发言间隔不超过 10 秒的普通跟进也会更新最后发言时间并触发回复。模型请求按用户串行，上一批生成期间收集的短句合并发出，带最近六条本轮发言与台词。HTTP 与旧 WebSocket 均从已认证用户读取公开昵称，在模型上下文中将昵称、正文与引用标为独立文本字段。大肥鱼开口时根据当前发言人的昵称自然称呼，缺少昵称时称为「岛友」。独立的本机内存缓存有长度、数量和时效限制，按用户隔离，间隔超过 10 秒后通过关键词另开一轮。明确引用来自已认证的 HTTP 发送链路。多实例部署依赖现有同一聊天室消息处理节点，短期上下文不跨实例同步。

复用已认证账号的 WebSocket。下行类型 `bigFish` 的 `data` 包含触发消息 `id`、`roomId`、`status` 和 `text`。公共室 `roomId` 为 `-1`。`thinking` 和 `error` 仅通知触发续聊的用户。成功台词以独立消息 ID、服务端角色身份及 `bigFish` 标记保存到现有房间消息表，再使用 `speech` 帧附带已保存的 `message` 广播。保存失败不广播成功台词。infrastructure 将实时及历史台词映射为同一种角色消息，列表沿用按消息 ID 合并与滚动分页。发送区按触发消息 ID 内联反馈等待和失败。客户端发送的内容不能指定角色身份或标记。

成功回复以 30% 的概率采用模型为台词选择的表情关键词。模型只可用预设的通用情绪词，服务端从台词尾部提取并校验该词，移除标记，以可选 `bigFishEmoticonKeyword` 随台词保存及广播。chat 在消息行挂载时经现有无凭证 `/emoticon-search` 端口读取首批候选，账号级表情控制器合并同词请求、复用结果并在登出时取消。按消息 ID 从排序后的候选中随机选一张，使同一组结果重复渲染时选图稳定。不同时间的搜索结果可能不同。旧 `bigFishEmoticonUrl` 继续展示。前端搜索只发送通用词，等待时复用紧凑加载反馈，空结果和搜索失败保留台词。普通聊天沿用图片预览和失败反馈，紧凑工作表沿用图片展开控件。

历史满页以最后一条消息的 ID 作为游标。大肥鱼台词处在页尾时，原样传回已保存的字符串 ID，后端在同一房间定位记录后沿用 `(createTime, id)` 分页。实时帧使用台词 ID 合并同一条历史记录，外层触发消息 ID 用于发送区反馈。

角色使用用户提供的 `https://oss.cqbo.com/moyu/pet/dapangyu.webp` 图集。普通聊天将放大的角色居中放入与普通消息一致的头像列，昵称和时间从共用起点排列。台词使用当前主题的默认接收气泡。工作表在台词所在单元格内并排展示角色与气泡，窄屏和紧凑工作表按可用宽度缩放。点击或用键盘激活头像、昵称时，沿用聊天草稿提及功能追加 `@大肥鱼` 并聚焦编辑器。可见消息行装载角色后播放短帧动画，保持每帧布局一致，减少动态效果偏好展示静帧。台词、时间与角色同属消息行。

## 替代方案

浮层会遮挡聊天内容。单独建表会重复房间分页、排序和撤回能力，当前使用群聊消息的服务器标记呈现角色形象。收藏库抽图和当前台词无关，也依赖个人账号；浏览器沿用已有表情搜索代理，服务端无需读取收藏或增加图片代理。AstrBot 会增加机器人运行时，直接接入 ReMe 可复用现有 DeepSeek 回复流程。ReMe 全工作区搜索会混入其他会话，使用按会话元数据过滤的专用检索 Job，并在后端逐项校验检索归属。

## 长期记忆

启用后，关键词触发和 10 秒内续聊在回复前按当前批次的文本检索 ReMe。后端以环境专属密钥和房间 ID、认证用户 ID 派生固定会话标识。ReMe `big_fish_search` 按 `session_id` 过滤 Markdown 索引，后端只接受同一会话的 `daily/` 卡片片段，每次最多三段。片段作为非指令资料提供给 DeepSeek，公共回复仅可在当前用户主动提起相关话题时引用适合公开的信息。

台词保存并广播后，由独立有界队列调用摸鱼助手现用的硅基流动 `Qwen/Qwen2.5-14B-Instruct` 识别本批发言中的记忆请求或明确自述的个人喜好。「我喜欢吃板烧鸡腿堡」这样的独立陈述即可记录，陈述后附「记住了吗」也是记忆请求。仅保留助手从用户正文中选出的原文片段，再调用 `auto_memory` 并要求 ReMe 按原意记录。寒暄、临时想法和明确要求别记的内容跳过。可以用同轮最近三条用户正文解析指代；引用、昵称、台词、表情包和随机插话不进入判断或写入。ReMe 将记忆笔记和提交的片段保存在持久化工作区。召回失败时用现有上下文回复。识别不到具体内容、助手返回无效片段、写入失败或队列已满时跳过本批，下一批继续处理。原 Redis 管理开关同时管控两条记忆路径。

通过后端 `fish.big-fish.reme` 配置 URL 和会话密钥，默认由服务端环境变量提供。部署说明见后端 `docker/reme-big-fish.md`。使用合成数据验证记忆写入、应用重启后的召回、按用户过滤、检索故障降级以及原有游标测试。

## 管理开关

管理页通过现有 admin 端口读取及保存 `/api/admin/big-fish/settings`，读写均要求管理员权限。启用状态存于 Redis 的 `chat:big-fish:enabled` 键，无过期时间，键缺失时默认开启。管理员明确保存后生效。大肥鱼工作线程在使用关键词、续聊或插话时读取状态，模型返回后再检查一次，关闭时丢弃尚未保存的台词并结束已经开始的等待反馈。Redis 读取故障沿用任务失败处理。相比静态 YML 或进程缓存，共享 Redis 允许管理员即时切换，聊天正常发送路径无需新增 Redis 读取。

## 验证

后端测试覆盖关键词命中、带 @ 的写法、10 秒滚动续聊边界、昵称来源和缺失回退、普通消息预筛、限频、模型静默、先保存后广播、表情关键词筛选、记忆请求与同轮指代、拒绝助手编造片段和故障时跳过写入，以及开关默认值、关闭时静默、待生成台词处理。前端覆盖畸形与重复帧、输入区等待和错误、角色对齐及默认气泡、短动画及减少动态效果、实时和历史表情包、搜索等待和空结果及故障、紧凑单元格展开、头像和昵称提及，以及设置加载失败、保存失败重试和刷新回读。按全部注册主题 × 明亮／暗夜 × 桌面／375px／390px 验证，执行 `npm run check`。合成模型和 WebSocket 测试与线上联调结果分别记录。

## 台词复读与戳一戳

台词通过既有复读动作以当前账号发送正文。桌面沿用气泡快捷操作，手机沿用长按菜单，角色消息保留独立呈现。大肥鱼头像复用 ADR-096 的手势及发送用例，单点和键盘激活头像仍可提及。消息菜单也提供戳一戳，使用同一发送用例，并保留草稿和引用。

HTTP 发送端口只额外接受大肥鱼的固定角色 ID 作为戳一戳目标，名称由服务端提供，后缀为空。沿用已认证发送者身份、禁言、三秒限频、幂等回执、保存、实时广播及撤回。角色无需用户表记录，戳一戳沿用互动消息规则，不触发 AI 回复或发言积分。相比为角色模拟用户或新增事件类型，复用固定身份和现有消息快照可直接支持历史与旧客户端正文。

按全部主题、明暗模式及桌面／375px／390px 验证台词复读、头像双击或连续轻点、菜单戳一戳、键盘及焦点、发送中、失败重试、成功去重和草稿保留。后端覆盖固定身份快照、幂等回执及其他保留 ID 拒绝。
