# ADR-064 签到迁移

日期：2026-11-14。状态：采用。

## 原因与影响

迁移旧版每日签到、月度日历及补签。domain/sign-in 定义模型和端口，infrastructure/sign-in 校验旧接口，features/sign-in 独立持有请求与交互，app 注入账号凭证，经账号资料的组合插槽提供入口。不将签到状态加入聊天或账号资料状态；账号变化卸载，关闭取消请求，主题和模式变化不重挂载。

沿用 `/api/user/signIn`、`/api/sign/status`、`/api/sign/month` 和 `/api/sign/makeup`。奖励及可补签资格由服务端决定，补签确认说明每次20积分、每月最多3次、最近7天限制。月历切换属于日期浏览，不是列表分页。

## 替代方案

2026-11-15：工作台导航增加常驻纯日历图标直达入口（无可见文字，保留无障碍名称和悬停提示），原个人资料入口保留。features/sign-in 新增账号作用域的轻量状态 Provider，由 app 注入账号及端口；两处入口共享今日状态，服务端明确返回未签到才显示 danger 语义红点，签到成功立即清除，失败/未知不伪造提醒。状态按日期隔离，跨日与重新回到前台刷新；账号切换取消旧请求。外观切换不重新请求，日历仍按需加载。不采用每个入口独立请求和本机推测签到结果，避免提醒不一致。验证全部主题明暗与三种视口、失败重试、签到后消点及焦点返回。

像素主题的导航签到入口在日历图标下显示“签到”，与相邻导航保持一致；手机底栏同步显示。由 app 注入可选导航文案，其他主题及个人资料入口保持既有呈现，不改变签到状态或请求。

不复制旧版巨型头像组件、Ant Design 或 moment；使用现有 Dialog、Button、ScrollArea 和原生日期计算。账号功能通过 ReactNode 插槽组合，禁止 feature 直接依赖其他 feature。

## 验证

适配全部注册主题、明暗、桌面及375/390px；校验请求取消、重复提交、失败重试、跨年日历、补签确认、滚动间距和焦点。执行 npm run check 及合成接口浏览器流程；真实账号操作不在自动验收中执行。

2026-11-15 直达入口验收：Chrome 合成接口覆盖 pixel-island、wps、wechat、wecom、feishu、dingtalk × light/dark × 1280/375/390px，状态未知/失败无红点、未签到提醒、失败重试、签到后消点、日历空状态、补签、触屏、Esc 与焦点返回、无横向溢出均通过。外观切换不重复读取签到状态；最终补验桌面像素/WPS/微信六组合通过。npm run check 通过（395 项单元测试）。临时浏览器配置、截图及报告验收后删除；真实账号与跨日/跨标签页实际运行未验证。
