# ADR-027：伙伴营地与二维分层场景

状态：采用。日期：2026-11-12。

## 原因与范围

将旧宠物养成模块迁至 `/pet`，采用原创伙伴营地命名和游戏面板。保留旧服务端养成、装备、外观和回合结算协议；不将场景内移动冒充联网探险，不新增实时群怪结算。页面、代码和资源不引入参考作品的专属称谓、角色或标志。

## 决策与影响

- domain/pet 定义领域实体和服务端端口；infrastructure/pet 校验 unknown DTO、处理 fetch/取消/鉴权；features/pet 拥有请求、交互和场景；app 注入服务与账号身份并懒加载。
- 使用原生 SVG 绘制原创斜俯视草地和独立景物，精灵以脚底锚点定位并按纵坐标排序。移动仅为本地营地互动，界面明确说明。无需新增依赖、Canvas 或三维引擎。
- 旧 WebP 动作表只应用于旧资源约定 `/moyu/pet/*.webp`，其他 URL 使用静态图片；加载失败显示可识别占位。素材无后端地址时不伪造已拥有宠物。
- 保留 `/api/api/pet/skin/*`、`/api/api/pet/rank/list` 等旧路径；不在迁移时擅自规范化。积分、冷却、胜负、装备属性由服务端决定，不以客户端动画决定收益。
- 排位挑战和幸运补给复用旧活动接口，积分消耗在提交前明确确认；不在前端生成奖励或伪造保底概率。活动状态独立于营地主数据，请求按打开面板懒加载。
- 单独请求的控制器有取消、卸载清理、重复提交保护。账号切换重建功能实例；主题和模式切换保持实例、面板状态及场景位置，不额外请求。
- 面板与操作使用已有语义变量和 shared/ui。场景插画使用 `--color-pet-*` 局部 token，明暗分别提供，不扩大第三方皮肤白名单。普通按钮遵循 ADR-026，表单弹窗遵循 ADR-025 的 reserved 滚动区。

## 替代方案

- 全量复制旧 Umi/Ant Design 页面：违反模块边界及单一 UI 技术栈，拒绝。
- 引入 PixiJS：大量实体和粒子场景时可重新评估；当前固定营地和回合演出无需新增运行时。
- 三维引擎：需要额外模型与动作资源，超出当前二维资源复用目标。

## 验证

执行 npm run check；以合成接口数据验证空营地、领养、养成、装备、外观、排行、挑战及错误恢复。按注册表全部主题 × 明暗 × 桌面/375px/390px 检查入口、场景、面板、无横向溢出、滚动间距与键盘/触屏操作；验证切换外观不重取、不丢业务状态。真实后端未联调时明确报告，不以合成浏览器结果替代真实接口验证。
