# ADR-040：旧版红包消息与领取

状态：已采用。日期：2026-11-13。

后续扩展：工具栏创建与发布红包由 ADR-042 补充，本记录保留消息展示与领取的原始范围。

## 原因与范围

聊天将旧协议 `[redpacket]ID[/redpacket]` 显示为原始文字。沿用旧摸鱼岛协议，按用户后续要求改为微信式橙金红包封面、信封与圆形封口、祝福语标题、独立底部操作区；红包消息移除外层灰色气泡。接入现有详情、领取（含答题）和记录接口；不新增发红包或管理员能力。

## 决策与影响

- domain/chat 负责红包消息解析、详情与记录模型及端口。标记大小写不敏感，ID 限制为 1～128 位字母、数字、下划线或连字符；无效标记保留原文。单条消息最多展示 12 张红包卡片，超出部分保留原文，避免异常内容产生大量详情请求。引用与复制显示 `[红包]`，复读沿用原文。
- infrastructure/chat 校验未知响应，以 Sa-Token 和既有过期处理访问 `/api/redpacket/detail`、`/grab`、`/records`。领取遵守后端 POST + query 参数协议；不记录答案、凭证或用户数据。
- app 注入端口。features/chat 使用账号隔离的红包控制器；每个红包独立 store，重复消息共享详情和领取状态；同红包仅一次领取请求在途，成功后禁止再次领取。无自动重试写操作；超时明确提示先查看记录，避免把未知结果显示为失败确定未领取。
- 消息行只负责呈现，红包控制器与草稿、消息列表分离。详情和记录支持取消与手动重试；卸载/账号切换释放请求。主题与模式不作为请求依赖。
- 默认明暗 token 增加局部 `--color-red-packet-*` 的封面、文字、边框、信封插画及结束态变量；答题红包沿用同一封面并明确标注类型。普通操作遵守共享 Button，底部操作区复用 surface/text/muted，记录弹窗复用 Dialog + reserved ScrollArea。手机操作至少 44px，说明换行，无固定最小宽度。
- 记录接口为一次性完整列表，无分页参数；本地按积分降序、稳定 ID 去重，不新增分页按钮，不把最高积分推断为唯一手气王。

## 替代方案

复制旧 Ant Design 组件会引入第二套 UI 框架及组件内 DTO 请求，违背依赖方向；只读卡片不能满足用户补充的领取需求。完整复制旧页面和增加创建红包功能均超出范围。

## 验证

单元测试覆盖协议解析、响应校验、领取互斥与失败恢复。浏览器覆盖全部注册主题 × 明暗模式 × 桌面/375px/390px，包含 loading/empty/error/success、答题、已抢完/过期、记录滚动、关闭及焦点返回、草稿和无横向溢出。执行 `npm run check`，结果与真实后端未验证项记录在 `docs/audits/chat-red-packet.md`。
