# ADR-054：保留评论的直接回复关系

状态：已采用。日期：2026-11-14。

## 原因与决策

前端把子回复的父 ID 替换为顶级评论 ID，后端只读取顶级评论的直接子项，导致多级回复被压平或遗漏。发送时保留实际被回复评论及其作者；沿用 parentId / replyUserId / children 协议，不增加依赖或通信入口。后端逐层批量查询当前页根评论的后代，以 ID 去重防止循环，再组装完整树。新增回复验证父评论属于同一动态，并以父评论作者作为被回复用户。删除评论同时删除其后代，按实际删除数量更新计数，避免不可达的孤儿回复。

前端逐级展开回复，发送成功后展开目标祖先链。列表采用独立回复行，最多保留两档缩进，深层回复通过嵌套结构及“回复某人”表达关系，避免手机内容持续变窄。解码采用迭代遍历，不再因正常深度大于八而拒绝整页。仅顶级评论展示置顶操作，与后端权限规则一致。

## 影响与替代方案

既有两层数据保持原有关系；历史上已压平的数据不能仅凭 replyUserId 唯一恢复父评论，不自动猜测或迁移。保留旧的两层协议或仅修改前端均无法返回真实后代；增加独立回复接口及根 ID 字段需要协议和数据库迁移，本次不采用。逐层查询成本随树深度增加，暂沿用当前评论分页粒度，后续有实测瓶颈再单独优化。

## 验证

单元测试覆盖深层解码、父评论校验、批量后代查询、树组装及删除计数。浏览器使用合成数据验证全部注册主题 × 明暗模式 × 桌面/375px/390px，覆盖逐级展开、回复目标、失败保留草稿、发送后回显、loading/empty/error/success、滚动与无横向溢出。执行 npm run check；后端运行相应用例并明确记录环境限制。
