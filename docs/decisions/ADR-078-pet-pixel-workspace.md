# ADR-078：像素伙伴工作台

状态：采用。日期：2026-11-15。

## 原因

伙伴页的大幅营地与九张入口卡片让装备、属性和行囊藏在弹窗内。同屏信息不足。按用户确认的像素设计稿改为紧凑游戏工作台。

## 决策与影响

- 沿用 ADR-027 的领域、通信与状态边界，不新增依赖、接口、演示任务或虚构货币。
- 桌面按可用容器宽度展示伙伴装备、营地挑战、行囊三栏；中等容器行囊另起一行，手机依次展示伙伴、营地挑战、行囊。图标入口保留可访问名称及原详细面板。
- 六个装备位、状态和属性来自 Companion；经验只展示实际值，不推测升级分母。行囊内嵌呈现与详细弹窗共用 ItemsPanel 的请求、操作与滚动分页。预览网格提供选中详情、穿戴和管理入口，不复制通信与养成逻辑。
- 详细面板内的物品变更使内嵌行囊失效刷新；喂食、主题或模式切换不重取行囊。外观切换不重挂载营地、丢失选择或重置分页。打开详细行囊是显式重新读取操作。
- 复用既有 color-pixel-* 明暗纸面、木框配色，主题 action 保留用于普通操作按钮。原始精灵与装备图片不反色。场景以原创阶梯路径和像素景物替换几何插画，不引入参考游戏资源。
- 内嵌行囊绑定独立 reserved ScrollArea，标题与详情不随网格滚动；触屏入口至少 44px，手机隐藏滑轨并保留 gutter。
- 养成成功将 care 返回的养成状态（伙伴编号、等级、经验、饱食、心情）合并到当前 Companion；服务端 feed/pat 仅复制基础实体，不提供装备与汇总属性，不能将缺失字段解码为空列表后覆盖完整资料。不重新读取 mine、不替换面板或显示成功横幅；仅失败反馈，提交中保留控件与现有数值。相比重新请求完整资料，此方式保留现有交互与请求数量；通过协议测试和全主题明暗、桌面/375px/390px 喂养及抚摸回归验证属性、装备持续可见。
- 自动喂食使用既有背包接口按 consumable 分类分页读取，领域保留 subType，只有 food、有效 code 且数量大于零的物品可选；同 code 合并数量。复用共享 Select 的 pixel 呈现与滚动分页，不要求填写内部编号。已保存但已耗尽的食物明确显示不可选，仍可关闭自动喂食；加载失败保留表单并可重试。
- 页面背景复用现有 home-island.png，明亮以既有海景 sky/canvas 语义色混合为底，插画 56% 透明度、居中贴底，使下方留白可以看到小岛；暗夜保留 canvas 基础背景，插画 32%。装饰层不影响正文、图片或交互。先前海岸图的图案被面板遮挡、下方海水又过淡，故替换为有明确岛屿主体的透明插画。
- WorkspaceShellSlots.contentFill 与共享 ScrollArea.fillContent 为显式纯布局选项，伙伴页面启用，使 Radix 内容包装层填满视口，背景在短内容/空/失败状态下也覆盖底部；默认关闭，不影响其他列表或滚动逻辑。图片后方的散步说明使用纸面底保证可读。
- 三栏桌面中，伙伴卡片不以属性数量撑高整行，左右卡片按同一网格行拉伸对齐；伙伴摘要显式启用 compact 呈现，压紧装备/状态间距，属性按可用宽度三列或四列排列，并使用 reserved ScrollArea 容纳超量内容。照料操作保持在卡片底部。中等容器两栏及手机单栏恢复自然内容高度，手机保留完整属性和触控尺寸；他人资料的默认摘要不受影响。

## 替代方案

- 将整张生成图用作背景：不可响应、不可访问且数据固定，不采用。
- 复制旧版宠物页面：重复业务、破坏分层，不采用。
- 一次加载技能与挑战奖励填充页面：增加无关请求且部分能力缺乏数据来源，不采用；保留既有面板按需加载。

## 验证

执行 npm run check。以合成接口覆盖全部注册主题 × 明暗 × 1440/375/390 视口的布局、加载/空/失败/成功、图标入口、选中详情、装备回读、真实滚动、挑战与焦点返回；检查主题模式切换不新增请求且保留位置与选择。浏览器测试不能替代真实后端联调。实际结果记录于 docs/audits/pet-pixel-workspace.md。
