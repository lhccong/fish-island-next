# ADR-062：迁移联机五子棋

状态：采用。日期：2026-11-14。

## 原因与决定

游戏目录接入旧版 `/game/piece` 五子棋，按 domain/gomoku（棋局纯规则与端口）、infrastructure/gomoku（旧协议校验与适配）、features/gomoku（独立对局控制器与界面）、app（鉴权、路由、注入）分层。不复制旧版页面或新增依赖。

复用账号唯一 WebSocket：infrastructure/chat 的连接增加可选原始帧扩展接口，由 app 将五子棋适配器接入；扩展不进入聊天消息 store，不额外创建连接。创建、加入与落子沿用 type=2 和 createChessRoom/joinRoom/moveChess，加入确认后开始，执黑先行。只处理当前房间、对方颜色、合法空点与当前回合；重复和其他房间帧忽略，异常顺序中止棋局。独立控制器跨路由保留内存对局，断线立即停棋并明确要求重新建房，登出清理。

旧后端只转发落子，无落子确认、棋盘快照、离房/认输/再来一局协议和断线补拉。因此本地发送成功后落子，不能保证对方收到；不自动重发、不伪造恢复、超时不自动判负。退出仅结束本机对局并说明对方不会收到离房通知；新局重新建房。未收到房间操作响应时提供明确超时失败及重试。收到超时后迟到的创建/加入确认不自动开局。

保留单机练习作为独立模式，AI 只在单机且确实轮到 AI 时运行。公共聊天邀请用既有 HTTP 发送协议和旧版 `[invite/chess]…[/invite]` 标记；聊天呈现可访问的加入链接。对局内聊天明确为公共聊天室而非私聊，使用 app 注入的现有聊天发送与订阅，避免复制第二套消息链路。

## 界面与影响

棋盘居中，房间信息和邀请/退出操作横排在顶部；桌面棋盘居左，右上为限高内部滚动的公共聊天室，右下为棋谱，窄内容区和手机按单列重排。按用户明确要求，点击或触屏点按棋盘直接落子，不设确认按钮；方向键移动焦点，Enter/空格直接落子。双方、回合、最后落点与五连结果有文字及形状提示。控件使用 shared/ui，所有主题与双模式使用语义 token；棋盘和棋子使用明确的局部明暗 token，不反色图片。外观切换保留棋局且不增加请求或连接。

替代方案：另建游戏 socket 会重复账号在线及心跳；复制旧全局状态会保留闭包、AI 串入联机和浅复制棋盘问题，均不采用。服务端权威判定需要独立后端协议，留待后续迭代。

## 验证

纯规则与控制器测试覆盖四方向五连、和棋、占位/越界/回合/房间校验、重复消息、断线、超时、退出与 AI 隔离。协议测试覆盖旧房间号与新对象响应、异常输入及出站字段。执行 npm run check；浏览器按全部注册主题 × 明暗 × 桌面/375/390 验证创建/加入、连续落子、胜负、失败重试、键盘和触屏、邀请与外观切换，检查布局和滚动。真实双账号生产联机若没有可用登录账号，明确标记未验证。

五子棋同时提供既有独立浮窗入口，页面与浮窗共用账号内单一对局控制器，关闭呈现或跨路由返回保留棋局，退出房间才主动结束本机棋局。
