# 组件与设计规范

本规范为强制要求。架构入口：[architecture.md](./architecture.md)。

## 1. 组件职责

| 类型     | 位置               | 可以做                         | 禁止                               |
| -------- | ------------------ | ------------------------------ | ---------------------------------- |
| 基础组件 | shared/ui          | 语义、交互、可访问性、视觉变体 | API、业务 store、业务字段、路由    |
| 业务组件 | features/<name>/ui | 单一业务展示、事件、精确订阅   | 直接连接后端、跨 feature 内部引用  |
| 外壳组件 | shells/<name>      | 布局、区域、平台呈现变体       | 复制聊天逻辑、连接与消息状态       |
| 页面     | app/pages          | 路由、组合、依赖注入           | 成百上千行状态、业务解析与请求堆叠 |

先按业务职责拆分，再按复用需要提升到 shared。只使用一次也可有独立组件；不能仅因两段代码相似就制造复杂通用组件。避免配置驱动的万能表单、万能消息组件、万能弹窗。

## 2. 文件与命名

```text
features/chat/
  index.ts                 唯一模块公开入口，显式导出
  model/                   store、用例、选择器、状态类型
  ui/
    MessageItem/
      MessageItem.tsx
      MessageItem.module.css
      index.ts
  lib/                     此 feature 专用纯函数
```

- 组件/类型 PascalCase；Hook 使用 use 前缀；工具函数 camelCase；目录按已采用约定一致命名。
- 一个文件一个主要组件；不在渲染函数内部声明组件类型，避免不必要的重挂载。
- 组件目标不超过 200 行；非空非注释行超过 300 会导致当前 lint 门禁失败，应按职责拆分。少量合理例外须 ADR 说明并局部豁免，禁止全局关规则。
- 不批量建立无实现目录；禁止超大 index.ts、循环导出、跨层 export *。

## 3. Props 契约

- 明确定义 Props；事件命名为 onSend / onClose 等，传业务意图，不传整个父组件 setter。
- 优先显式标量、实体 ID 和最小视图数据，不透传整份 store 或大对象。
- 可复用控件使用受控 value/onChange；确需非受控时用 defaultValue，并说明两者互斥约束。
- 使用判别联合表达状态，避免 loading、error、success 多个布尔值组合出矛盾状态。
- children、slots 仅在真实组合场景使用。不要为未知需求添加十几个可选 props。
- DOM 包装组件继承原生属性、默认按钮 type="button"，正确透传 aria/data 属性和 ref；使用 Radix asChild 时尤其要验证事件与 ref。
- 禁止 props 变异、JSON 深拷贝、数组下标作为动态列表 key、在渲染中产生随机 ID。

## 4. 状态与副作用

- 可由 props/store 推导的数据直接推导，不再用 effect 同步一份状态。
- effect 只用于连接外部系统，并有对称清理；不能用它串联业务状态机。
- store 按功能划分、通过 selector 订阅；选择多个值时使用稳定结果或浅比较。禁止 useStore() 订阅整个聊天状态。
- 输入框保持本地/独立草稿状态；输入法 composition 期间不能把 Enter 当作发送。
- 网络和缓存经注入用例调用；组件不感知后端 DTO。错误由功能界面决定如何展示。
- memo/useMemo/useCallback 根据订阅边界和测量使用；不能用大量缓存掩盖错误状态结构。

## 5. 视觉系统

- 颜色、间距、圆角、阴影使用语义 token；原始色值只存在默认 token 和皮肤配置。布局断点、图标尺寸等结构值可以是常量。
- 全局 CSS 限制为 reset、基础排版、默认 token、可访问性规则。组件样式放同目录 CSS Module。
- 不使用全局 .ant-* 覆盖、深层后代链、随意 !important；减少动效的可访问性覆盖是明确例外。
- 样式目标清晰，禁止靠 DOM 层级猜测业务状态；用显式 class/data 属性表达状态。
- 统一字号层级、间距阶梯、图标线宽和交互高度；普通可点击控件至少 44px 高，密集桌面场景另行验证。
- 聊天区布局用 flex/grid；滚动容器明确 min-height: 0，避免多层滚动和硬编码视口减法。
- 文字区可选择、长 URL 可换行；图片保留比例；窄屏隐藏次要区域而不压坏消息和输入框。

## 6. 交互和可访问性

- 使用 button、a、input 等语义元素；图标按钮必须有可访问名称，装饰图标 aria-hidden。
- 菜单、对话框、提示优先包装 Radix；验证 Tab、Escape、焦点锁定和关闭后焦点归还。
- 主内容和独立长列表统一使用 shared/ui/ScrollArea，保留键盘和触屏原生滚动，避免嵌套多个同方向滚动容器。滚动视口必须有可访问名称；仅在切换内容身份时重置滚动位置，搜索和刷新不强制跳底。
- 固定高度的热榜卡片是明确的局部滚动场景，可在总览滚动区内独立滚动；卡片头尾固定，正文区 min-height: 0。输入工具栏通过外壳 footer 独立布局，不跟随消息滚走。演示控件须标注演示，不伪造真实请求或成功结果。
- 每个功能覆盖 loading、empty、error、ready；异步操作有发送中、成功或失败反馈，防止重复提交。
- 焦点清晰可见，状态不能只靠颜色区分；验证正文对比度与 prefers-reduced-motion。
- 带图标/按钮的复合输入框只在外层容器提供 focus-within 焦点提示；内部 input 的 focus 和 focus-visible 不得再叠加 outline、边框或阴影，避免双重内边框。
- 手机热榜来源使用现有 Dialog 与 ScrollArea 组合选择面板，提供搜索、当前项勾选和关闭后焦点归还，避免原生 select 长菜单覆盖聊天区域。按产品要求，消息输入区不展示“界面演示”提示；未接入的发送与工具按钮保持禁用。
- 不在整个消息流滥用 aria-live；仅使用独立且节流的辅助通知，避免读屏重复朗读历史消息。

## 7. 评审清单

- 模块位置、状态所有权、Props 边界是否明确？
- 新消息或每次输入会更新哪些组件？历史增加是否影响已有消息行？
- 是否能脱离后端用数据与回调演示表现组件？
- 样式是否支持不同皮肤、长文本、图片加载与窄屏？
- 是否有副作用清理、取消与失败路径？
- 是否通过 check，并验证变更涉及的实际交互？
