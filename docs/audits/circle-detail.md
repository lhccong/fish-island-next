# 互动通知关联动态详情验收

日期：2026-11-12。使用独立生产构建预览、Playwright Chromium 与合成接口响应，不包含真实账号或聊天数据。

范围：通知中的关联动态在工作台主内容区切换为详情，关闭通知浮层；详情无 Dialog、Portal 或遮罩。微信式作者/正文/图片/时间/互动区和固定返回入口；手机占满主内容区域。复用现有点赞、评论、图片预览及权限逻辑。

自动化入口：`npx playwright test --config playwright.circle-detail.config.ts`。配置自动在 `node_modules/.cache/circle-detail-inline-preview` 生成独立构建，并在 43128 端口预览，避免其他开发服务器的编译与端口冲突。

矩阵：WPS 表格、微信绿、企业微信、飞书蓝、钉钉蓝 × 明亮/暗夜 × 桌面 1280×720、手机 375×812、390×844，共 30 个组合。

本轮结果：页面内切换后的 30 个组合全部通过；`npm run check` 通过（格式、lint、类型检查、120 项单元测试与生产构建）。上一版详情弹窗的验收不适用于当前行为。构建保留项目原有的大体积 chunk 提示。

检查内容：

- 打开时展示 loading；详情失败后原位重试；已读失败不阻止阅读，返回列表仍可看到失败反馈。
- 正文、九宫格、点赞与评论空状态；点赞操作；评论输入与聚焦；图片预览、Esc 关闭与焦点返回。
- 返回鱼小圈恢复列表滚动位置和评论草稿，聚焦消息通知入口，不重复请求列表；未迁移通知显示实际限制，不请求不存在的动态。
- 详情内部无横向溢出，桌面 24px、手机 20px 固定 gutter；手机滑轨隐藏，触屏滑动可滚动；桌面滚轮滚动，返回按钮保持可达。
- 本轮每个组合保存成功与错误截图到 `test-results-circle-detail-inline/`（运行时使用同名 output 覆盖默认目录）。人工抽查微信桌面、手机及暗夜截图的层级、间距和文字可读性。

限制：未连接真实后端验收；未在实体手机上验证系统软键盘与浏览器安全区域；未覆盖 Safari、Firefox。未迁移的非动态帖子详情仍明确提示不可用，未新增该业务接口。
