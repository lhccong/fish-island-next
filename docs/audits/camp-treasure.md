# 营地挖宝验收记录

日期：2026-11-16。实现依据：[ADR-094](../decisions/ADR-094-camp-treasure.md)。

## 交付行为

五处地点任选，挖掘五秒后由服务端结算等概率的 1–10 可用积分。账号每天（北京时间零点）最多开始五次；初始一次机会，每次挖掘结束时刻起一小时恢复一次，不累积。跨零点保留正在挖掘的记录和小时冷却。开始占用次数，刷新、断网和重复结算不会凭空增加机会或奖励。

场景显示铲子、土尘、光点和进度。五秒结束停止挖掘动画；结算失败保留记录并提供重试。减少动态效果时保留静态表现。领取后刷新账号积分；余额刷新失败与领取失败分别提示。

## 2026-11-17：真实时间戳协议回归

用户反馈正常接口仍显示“挖宝状态异常”。根因是后端 JsonConfig 将 long/Long 转成 JSON 字符串，而原前端适配器和模拟夹具只按 number 处理，未覆盖真实序列化协议。本轮只在通信适配层严格归一化十进制时间戳字符串，不修改界面、每日次数、冷却或积分结算规则；初始的 nextAvailableAt="0"、挖掘中的 readyAt 和已结算的冷却时间均已覆盖。领域内继续使用 number，非法值和不安全整数仍拒绝，计数与奖励仍保持 int 数字协议。

- `VITEST_MAX_WORKERS=4 npm run check` 全部通过：111 个文件 / 479 项单元测试、格式、lint、类型及构建。构建保留前述现有大包与动态导入警告。
- 新增后端 `PetTreasureSerializationTest`，经实际 JsonConfig 和 BaseResponse 序列化验证 long 字段为字符串、int 字段为数字：1 项通过，0 跳过。运行 `mvn -q -Dmaven.test.skip=false -Dtest=PetTreasureSerializationTest test`，无需数据库或 Redis。
- 浏览器夹具默认返回真实的字符串时间戳，重跑上述全部七主题 × 明暗 × 1440/375/390 的 45 项用例，包含加载、无伙伴、失败重试、五秒挖掘、领奖、小时冷却、每日上限、恢复、换肤、触屏及键盘。首轮 44 项通过；WPS 暗夜 390px 在模拟加载释放后等待按钮恢复可用超时，独立重跑通过（10.0 秒），稳定成因未确认，未将此首次失败计为直接通过。
- 本次只需更新前端构建，无需为本次协议修复修改数据库或后端业务接口。真实用户账号的接口、积分到账、MySQL/Redis 联调仍未执行。
