# 聊天首次历史加载验证

日期：2026-11-12。决策与阶段边界见 ADR-036。

## 当前行为

首次打开公共聊天室，通过带 Sa-Token 请求头的 POST `/api/chat/message/page/vo` 获取最近 50 条；请求为 `roomId:-1/current:1/pageSize:50/sortField:createTime/sortOrder:desc`。上翻使用最早记录的字符串 messageId 游标，按滚动边界自动读取，不展示页码或加载更多按钮。

历史与实时共用 ReceivedMessage 解码和归一化 store。历史合并前先提交待处理实时事件，重复 ID 仅保留一条，实时实体优先、撤回墓碑不可被旧正文覆盖。独立历史控制器负责串行请求、取消、代际校验、错误重试、重复/空页停止；MessageStream 仅订阅 IDs、索引与必要状态。Virtuoso firstItemIndex 保持上翻锚点，状态 Header 通过共享 InfiniteScroll 观察实际 ScrollArea 视口。

账号内返回页面保留已加载窗口，未完成请求会取消；首次请求被取消后重新进入可重试。主题、明暗与头像设置不会重置历史。刷新页面重新加载，不把聊天正文持久化到浏览器存储。

## 已验证

- Windows、Node v25.8.1、Playwright Chromium；浏览器为 Vite 开发模式。生产构建另由 check 验证。
- `npm run check` 通过，39 个测试文件共 146 项单元测试通过；生产构建仍有原人生重开异步块超过 500kB 的提示。
- `node node_modules/@playwright/test/cli.js test -c playwright.chat-history.config.ts --workers=4 --trace=off`：90/90 通过。包含历史新流程 30 项，以及头像图片、实时消息两组各 30 项回归。
- 覆盖 wps/wechat/wecom/feishu/dingtalk × light/dark × 桌面 1280×720、手机 375×812/390×844。
- 合成历史数据为 150 条，分三批 50 条及最终空页；注入并发实时消息、重复 ID、先到撤回事件。每个组合验证首次加载中、首次 503 后重试、历史/实时去重、实时正文优先、撤回不恢复、上翻续读 503 后重试、连续游标、空页终止、上翻锚点偏差小于 5px、返回最新、无横向溢出及虚拟 DOM 少于 80 行。
- 每个组合验证草稿保留与单一 WS 连接；桌面额外切换主题/模式，检查 HTTP 请求数量不增加。手机使用触屏重试与返回最新；实时回归包含实际合成触屏拖动。
- 单元覆盖历史包装 DTO、头像字段、长整数 ID 保留、畸形响应、认证与首批/游标参数、HTTP/业务失败、历史与实时/撤回并发合并、请求串行、重复页停止、取消及迟到响应忽略、窗口上限停止。
- 已查看 WPS 明亮桌面及微信暗夜手机截图，检查消息流、连接提示、输入区和换行；截图/trace 属于本次临时产物，记录结论后清理。

## 限制与未验证

- 当前仅保留最近 1000 条消息；达到预算后停止继续读取，明确提示窗口边界，不显示“历史已全部加载”。未实现双向页逐出/回读，不能浏览无限历史。
- 此接口向旧消息读取；没有确认断线期间 seq/cursor 补拉协议，仍可能漏收断线期间的消息。发送保持禁用。
- 未使用真实账号联调后端，包括字符串长整数游标接受情况、特殊历史记录类型及实际权限失效响应；当前按旧前端实际协议适配。
- 未实测超高视口短列表自动填充、所有键盘/焦点/悬停组合、真实手机软键盘及物理设备。共享边界组件保留短列表自动按需加载能力，但本轮数据分页的每页超过标准视口高度。
- 未进行 1 万条历史回看、30 分钟稳定性、持续输入 p95、掉帧/长任务和堆内存趋势测量。构建主 index 块 gzip 约 112.06kB，未汇总入口同步依赖链，不能据此宣称首屏预算达标。
