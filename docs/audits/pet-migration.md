# 伙伴营地迁移记录

日期：2026-11-12。决策：[ADR-027](../decisions/ADR-027-companion-camp.md)。

## 实现范围

入口为发现菜单的“伙伴”，路由 `/pet`，沿用现有账号守卫。领域实体、HTTP 适配、功能控制与表现、app 组装分别归属 domain/pet、infrastructure/pet、features/pet、app，跨模块通过公开入口访问。没有新增运行时依赖或第二套 UI 技术栈。

| 旧能力                 | 新入口及行为                                             |
| ---------------------- | -------------------------------------------------------- |
| 创建、改名、喂食、抚摸 | 空营地领养、伙伴档案、营地快捷操作；服务端校验积分与冷却 |
| 自动喂食               | 独立配置面板，保存后回读；物品手册展示食物编号           |
| 皮肤                   | 外观，分页、兑换确认、使用后刷新营地主数据               |
| 背包、穿脱装备         | 行囊，分页物品、当前装备、穿戴与卸下                     |
| 分解及批量分解         | 行囊，两种操作均在确认后提交，结果由服务端返回           |
| 商店、物品图鉴         | 补给铺、物品手册，分页查看；购买前展示积分消耗           |
| 装备升级、刷新与锁定   | 锻造台，明确费用、概率、锁定状态；不将升级失败显示为成功 |
| 宠物排行榜、他人详情   | 挑战 → 伙伴排行；只读伙伴资料与切磋入口                  |
| 首领与伤害排行         | 挑战 → 首领挑战、贡献排行                                |
| 排位、爬塔             | 挑战 → 每日排位、逐层试炼；胜负/积分来自服务端           |
| 转盘活动及记录         | 幸运补给，单次/十次领取、消耗确认、实际奖励及历史记录    |

营地为原创 SVG/CSS 二维分层场景，采用脚底锚点、独立阴影和纵坐标遮挡排序。WASD/方向键按住连续移动，支持组合方向；鼠标点击及触屏轻点设置目的地。朝向以实际位移判断，垂直移动延续水平朝向，停止回到待机；失焦、页面隐藏、打开浮层或输入文字时停止/不截获按键。不新增联网探险、碰撞战斗、捕获或群怪结算能力。

## 协议兼容与边界

- 沿用现有动态 Sa-Token 请求头与后端隔离凭证存储，不新增认证持久化。请求取消、超时、认证过期和重复提交分别处理。认证失效进入现有恢复流程。
- 保留旧服务端的双 `/api` 外观/排行路径。改名提交 `petId`，他人详情提交 `otherUserId`。鉴权读取和旧版以 GET 提交的挑战均禁用 HTTP 缓存。
- 旧动画契约为每帧 192×208、8 列、9 行。按已解码的 1536×1872 尺寸识别图集，避免资源地址换目录后失去动作。其他图片静态显示，不猜测任意图片的动作布局；加载中/失败有占位，不替换成虚构的已拥有资源。
- 仅营地插画使用局部语义配色；面板、控件和反馈跟随所有注册主题及明暗模式。普通按钮沿用 shared/ui/Button，表单/卡片面板使用 reserved 滚动区，保留手机安全区域和关闭入口。
- 切换主题和模式不改变功能实例、营地位置或当前业务状态，不额外请求。账号改变重新建立功能实例并释放旧请求/计时器。

## 验证方式

```powershell
npm run check
npx playwright test --config playwright.pet.config.ts
npx playwright test --config playwright.pet-direction.config.ts
```

浏览器使用独立生产构建、独立端口和输出目录，避免复用旧预览服务或受开发热更新影响。主流程包含三个测试集合：养成与所有面板/异常状态、积分确认与真实回包语义、资料/贡献榜/批量分解。方向专项使用仓库保存的既有 luobo、wutiaowu 两张图集，检查实际 CSS 帧裁切、连续换向、WASD/方向键持续移动、目标未抵达时改变方向、停止待机、失焦、输入隔离及手机触屏。此前仅用合成动作表的结果不能替代真实素材方向验收。

矩阵按 `src/skins/builtin` 注册表生成：WPS 表格、微信绿、企业微信、飞书蓝、钉钉蓝；每种明亮/暗夜模式 × 桌面 1440px、手机 375px、390px。检查页面与面板内部无横向溢出，显示滚动条并检查预留间距及顶部/中部/底部，使用 Radix 选择器与确认弹窗检查焦点返回，验证主题/模式切换不重取和不丢位置。截图位于 `test-results-pet-first-pass/`、`test-results-pet-final/`、`test-results-pet-direction/`，为合成账号、数据和图片，不包含真实聊天或账号资料。

初次迁移执行结果：伙伴领域/协议单元测试 7 项通过；定向类型检查及生产构建通过。主回归首轮 81/90 通过，修正成功/加载状态选择器歧义及页面就绪等待后，剩余 9 项重跑通过；当时使用合成图的方向专项首轮 29/30 通过，一项浏览器 page 初始化超时，单独重跑通过。合计覆盖 120 个不同场景，并非一次执行全部无重跑通过。

初次迁移期间曾完整通过 `npm run check`（当时全仓 101 项单元测试），随后有被其他并行改动格式检查阻塞的执行记录，未修改这些文件以规避门禁。后续方向与 WASD 修复的最终版本已重新通过完整 `npm run check`，全仓 118 项单元测试通过，格式、零警告 lint、类型检查与生产构建均通过。

## 方向与 WASD 修复

2026-11-12 的后续方向修复采用真实 luobo 和用户指定 wutiaowu 图集（原样保存于 tests/fixtures/pet），通过图片解码尺寸识别图集。两者左右行顺序相反，分别登记资源动作配置，不能全局互换行号。以实际位移驱动朝向，消除目标点和 650ms CSS 插值之间的朝向不一致；WASD/方向键连续控制、快速改目标、失焦停止、输入隔离、关闭面板后的按键恢复均纳入专项矩阵。伙伴相关单元测试扩为 13 项并通过；全仓最终 118 项通过。两张原图没有上下跑动动作，垂直移动延续最近的水平朝向。

最终真实图集专项一次执行 60/60 通过（两张资源 × 五主题 × 明暗模式 × 1440/375/390px），包含实际左右帧偏移、WASD 与方向键、触屏、改目标、失焦停止、输入框隔离和关闭面板后的控制。此处的结果取代先前仅使用合成动作表的方向验收结论。
