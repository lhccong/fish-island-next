# 连续消息复读验收

日期：2026-11-13。开发模式，Windows 本机 Playwright Chromium，全部数据为合成夹具，未使用真实账号或聊天记录。

## 实现范围

连续两条相同的已确认正文在第二条气泡右侧显示圆形 +1；直接发送原文，不修改输入草稿或引用。发送中防止重复点击，失败保留原列表并提供已有发送重试。第三条确认成功后合并，仅改变展示，不改服务端实体；头像圈按账号去重，改为气泡右下沿的一排 20px 圆头像，与气泡间距 4px；移除展开按钮、可见昵称、称号和次数，参与者信息保留在头像提示及无障碍标签中。撤回后重新拆分。支持图片正文；红包、引用、撤回、失败、发送中和空白消息不合并。

称号编号/名称兼容表取自旧客户端公开配置，缺失与未知编号明确反馈。旧配置仅有图片、名称为占位值 0 的称号不伪造名称，显示“称号未收录”；不调用仅返回本人称号或要求管理员权限的接口。

## 已验证

- 主题：WPS 表格、微信绿、企业微信、飞书、钉钉，均覆盖明亮/暗夜。
- 视口：1280×720 桌面、375×812、390×844。30 个组合核心用例通过（布局调整过程中的 WPS 桌面两例在最终代码下单独重跑通过）。
- 空列表与首次成功接收、两条触发阈值、发送中禁用、失败提示及原命令重试、HTTP/WS 去重确认、三条合并、紧凑头像条、无可见名称及展开按钮、撤回拆分。
- 桌面键盘 Enter 触发、375/390 触屏 tap 触发；44×44 命中范围、按钮位于第二条右侧、长 URL 换行和受影响容器无横向溢出断言。
- 切换主题和明暗保留分组与草稿，不新增历史请求或连接。手机聊天内页按现有设计无主题按钮，测试临时切至桌面宽度使用既有入口，再恢复手机宽度验证业务状态。
- 本轮实际查看微信暗夜桌面和 375px 截图，检查气泡右下沿的紧凑头像条、+1、无名称与展开按钮。截图与测试追踪为临时产物，提取结果后清理。
- 单元测试覆盖精确比较、分隔条件、图片/红包、确认与失败、撤回、实体保留、历史前插索引、复读并发保护及未知头衔。

## 检查及限制

本轮执行 npm run check，仍被任务开始前已有的 .tmp-composer-validation/.last-run.json 格式问题阻断，不修改其他任务产物。当前独立 npm run lint、npm run typecheck、npm run test（56 文件/234 用例）、npm run build 均通过。变更文件单独检查格式。

截图反馈后的布局断言覆盖头像 20×20px、单排高度、与气泡间距不超过 5px、昵称/称号不占可见布局、无展开/收起按钮；仍覆盖原复读发送中、失败重试、撤回拆分、草稿和换肤状态。动效结束后再量测，避免缩放过渡造成尺寸误判。

未验证真实服务端联调、实体手机软键盘、屏幕阅读器、长期高频消息和长历史滚动性能；无性能采样或体积预算达标结论。构建仍有既有人生重开大分块提示。未新增原生 select 或业务浏览器确认框。
